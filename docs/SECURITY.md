# Безопасность

Описывает реализованные меры, способы их проверки и известные ограничения. Модель угроз: внутренний сотрудник с избыточным любопытством, гость/подрядчик, скомпрометированная учётная запись, вредоносный файл или вставленный контент, ошибка администратора, потеря инфраструктуры.

## Авторизация

* Все проверки — на сервере (`acl/engine.ts`); UI только скрывает недоступное.
* Недоступные страницы — 404 (не раскрывается существование); поиск, дерево, обратные ссылки, хлебные крошки, вложения, экспорт фильтруются по правам **до** формирования ответа.
* Наследование с границами, явный запрет, гости не входят в «всю организацию», личные пространства недоступны администраторам без явной выдачи.
* Расширение аудитории требует подтверждения с предпросмотром, кто получит доступ.
* Экспорт и скачивание — отдельные права и политики пространства.

## Контент пользователей

* HTML (вставка, импорт) — один allowlist-нормализатор для браузера и сервера (`packages/shared/src/editor/html-normalize.ts`, D-38: скрипты, обработчики, формы, встроенные объекты, чужие стили и пиксели отслеживания удаляются), затем построение узлов только по схеме документа и проверка URL (`finalizeIngest`, `sanitizeDocUrls`); ссылки только безопасных схем (`sanitizeHref`: http/https/mailto/tel/относительные), `javascript:`/`data:` в ссылках отбрасываются. HTML, который хранится или отдаётся как HTML, очищает `sanitize-html`.
* SVG — очищается от скриптов и обработчиков событий при загрузке.
* Файлы отдаются с `X-Content-Type-Options: nosniff`, `Content-Disposition`, CSP `default-src 'none'; sandbox` (PDF — без sandbox, но без скриптов и только для встраивания самим приложением: встроенный просмотрщик браузера отказывается работать в песочнице).
* Исполняемые файлы (PE/ELF/скрипты с shebang и маскировкой расширения) отклоняются.
* Антивирус ClamAV (`CLAMAV_HOST`, протокол clamd INSTREAM) проверяет вложения, изображения по ссылке, импорт (каждый файл и вложения внутри ZIP/DOCX) и восстановление архивов. **Fail closed**: файл принимается только после ответа `stream: OK`; отказ соединения, тайм-аут (`CLAMAV_TIMEOUT_MS`, 60 с), обрыв или любой другой ответ (например, превышение `StreamMaxLength`) — файл не принимается, пользователь видит «Антивирусная проверка недоступна — файл … не принят. Повторите позже.» (HTTP 503 `av_unavailable`; слишком большой для clamd — 413 `av_limit`). Метрики `kb_antivirus_up` (PING при каждом сборе) и `kb_antivirus_scans_total{result}`; алерты `KbAntivirusDown`, `KbAntivirusScanErrors`, `KbMalwareRejected` (`deploy/monitoring/prometheus-alerts.yml`, runbook `docs/OPERATIONS.md` §7.6.3). Проверено с реальным clamd 1.5.4 и официальной базой сигнатур (main 63, daily 28162): `KB_TEST_CLAMAV_HOST=127.0.0.1:3310 npx vitest run --project resilience tests/resilience/clamav-real.test.ts` — EICAR и EICAR внутри ZIP отклоняются и аудируются, чистые файлы сохраняются побайтно, при остановленном и «зависшем» демоне загрузка и импорт отклоняются с понятным сообщением (восстановление архива идёт через ту же проверку `assertClean`, с реальным демоном отдельно не прогонялось), метрика опускается в 0 и поднимается после восстановления.
* Изображения других сайтов во **вставленном** HTML копируются сервером тем же SSRF-защищённым загрузчиком (`POST /api/v1/attachments/from-url`, `services/remote-fetch.ts`), браузер к чужому сайту не обращается: CSP приложения разрешает картинки только `'self' data: blob:`. В документе видно «Копирование изображения с другого сайта…», при неудаче — «не скопировано — читатели его не увидят» с кнопкой «Повторить» и итоговое уведомление; вставка остаётся одним шагом отмены (`apps/web/src/editor/clipboard/remoteImages.ts`, `tests/e2e/paste-external-images.spec.ts`).
* Импорт ZIP: защита от zip-slip, абсолютных путей, символических ссылок, зашифрованных записей и «zip-бомб» (лимиты числа, размера, коэффициента сжатия).
* Mermaid рендерится с `securityLevel: 'strict'`; формулы — KaTeX без `trust`.
* CSP приложения: `script-src 'self'`, `img-src 'self' data: blob:` (никаких внешних картинок: аватары — инициалы, публичные страницы отдают вложения по своим адресам `/pub/<token>/files/…`), `frame-ancestors 'none'`, `frame-src` — только своё происхождение и разрешённые видеохостинги (YouTube-nocookie, RuTube, VK), `object-src 'none'`. Проверяется `tests/integration/security-headers.test.ts`. Картинки, вставленные внешними ссылками **до** этого изменения, при обновлении копируются на сервер автоматически: миграция `0030` ставит фоновую задачу `localize-images` для каждой организации (`services/localize-images.ts`, тот же SSRF-защищённый загрузчик). Документ переписывается через хаб совместного редактирования, открытые редакторы получают изменение. Недоступные картинки остаются ссылками и перечисляются в результате задачи (`jobs.result.failed`). Тест — `tests/integration/localize-images.test.ts`.

## Ограничение частоты запросов (SEC-L4)

* Лимиты, важные для безопасности, — общие для всех экземпляров приложения: счётчики в PostgreSQL (`rate_limit_counters`, UNLOGGED, фиксированные окна по часам БД, ключи хранятся только хешем — ключом может быть cookie сеанса). Это вход по паролю, принятие приглашения, начало и завершение входа через SSO (`AUTH_RATE_LIMIT_PER_MINUTE`), пароль публичной ссылки — по адресу (10/мин) и по ссылке со всех адресов вместе (`PUBLIC_LINK_ATTEMPTS_PER_LINK_PER_MINUTE`, 30/мин; отказ аудируется), начало загрузок — вложения, изображения по ссылке, сеансы докачки, импорт, восстановление архива (`UPLOAD_RATE_LIMIT_PER_MINUTE`, 120/мин на сеанс). Маршрут подключается флагом `config.rateLimit.distributed`.
* Быстрый путь: ключ, превысивший лимит, отклоняется экземпляром локально до конца окна, без запроса к БД; один счёт — один `INSERT … ON CONFLICT DO UPDATE`. Если PostgreSQL недоступен, лимит временно считается локально (сбой БД не превращается в блокировку входа). Общий лимит API от перегрузки (`RATE_LIMIT_PER_MINUTE`) остаётся на экземпляр.
* Проверка: `tests/resilience/rate-limit-global.test.ts` — два процесса сервера на одной БД, запросы попеременно: вход, загрузки и пароль ссылки ограничены суммарно, как на одном экземпляре; быстрый путь не обращается к БД.

## Публичные ссылки, экстренный доступ, локальные копии

* Публичные ссылки (`/pub/<token>`): выключены политикой организации по умолчанию; в БД хранится только хеш токена; срок, пароль (argon2id, неверные попытки аудируются, rate limit), `X-Robots-Tag: noindex` и `<meta name="robots">` по умолчанию, скачивание вложений — отдельный флаг и политика пространства; отзыв, выключение политики или потеря автором права делиться останавливают ссылку немедленно. Перед созданием пользователь подтверждает, что скачанное отозвать нельзя.
* Экстренный доступ администратора — см. `DECISIONS.md` D-24: два администратора, основание, срок, только чтение, уведомление владельца, аудит.
* Локальные копии документов в браузере (IndexedDB) используются без сети не дольше 30 дней; при ответе сервера «нет доступа/не найдено» копия удаляется с устройства (неотправленные правки не уничтожаются молча). `apps/web/src/sync/localCopies.ts`.

## Аудит

Журнал `audit_events` — только добавление (триггер запрещает изменение/удаление), каждая запись содержит хеш предыдущей (канонический JSON). Проверка целостности: `npm run audit-verify` или «Администрирование → Журнал аудита → Проверить». Логируются входы, изменения прав, экспорт/скачивание, администрирование, восстановление, архивы, открытие документов (`page.view`, не чаще раза в 10 мин на пользователя и документ), логические операции правки (`page.edit`), обращения к скрытым ресурсам (`access.not_found`) и отказы (`access.denied`), публичные ссылки и экстренный доступ.

## Данные и секреты

* Секреты только через переменные окружения (`deploy/env.example`); в репозитории секретов нет. В production сервер не стартует с коротким `SECRET_KEY` или заглушкой вида `CHANGE_ME…`.
* Шифрование при хранении обеспечивается инфраструктурой (диск/СУБД/S3 SSE); резервные копии — с шифрованием (см. `BACKUP_RESTORE.md`).
* Корзина и сроки хранения, legal hold блокирует безвозвратное удаление.

## Известные ограничения (честно)

1. Нет независимого тестирования на проникновение; DAST — собственный baseline (`tests/support/dast.ts`), OWASP ZAP не запускался. Пробелы ASVS L2 перечислены в `docs/ASVS.md`. В dev-зависимостях 2 moderate в `@vitest/mocker` (браузерный режим vitest не используется) — приняты со сроком до перехода на vitest 4.1.12.
2. OIDC и ClamAV проверены с реальными сервисами в тестовом окружении (panva/oidc-provider, clamd с официальной базой), но не с корпоративным IdP заказчика (Keycloak/ADFS/Azure AD — проверить на стенде: имена claims групп/отдела, post-logout redirect URI). Back-channel logout от IdP не поддерживается: выход в IdP не завершает уже открытые сеансы базы знаний (их срок — `SESSION_TTL_HOURS`/`SESSION_IDLE_HOURS`, администратор может отключить пользователя). Конфигурация TLS nginx тестами не проверяется.
3. Открытая находка SAST (низкая, только клиент): выражение `NUM` в `apps/web/src/editor/tableOps.ts` квадратично на ячейке из ~50 000 пробелов с буквой в конце (≈2,5 с подвисания вкладки автора); исключение записано в `scripts/security/sast-rules.js`. Lighthouse: у скелета редактора `aria-label` без роли (`aria-prohibited-attr`, `apps/web/src/editor/Editor.tsx`).
4. Изображение, которое сервер не смог скопировать при вставке (сайт недоступен, требует входа, не картинка, внутренний адрес), остаётся в документе внешней ссылкой и не показывается (CSP); автор видит это и может повторить или вставить файл. Если автор закроет вкладку до окончания копирования, оставшиеся картинки остаются внешними ссылками.
5. Общий лимит API от перегрузки (`RATE_LIMIT_PER_MINUTE`) считается на экземпляр; глобальны только лимиты входа, паролей ссылок и загрузок.
