# Безопасность

Описывает реализованные меры, способы их проверки и известные ограничения. Модель угроз: внутренний сотрудник с избыточным любопытством, гость/подрядчик, скомпрометированная учётная запись, вредоносный файл или вставленный контент, ошибка администратора, потеря инфраструктуры.

## Аутентификация и сеансы

| Мера | Реализация | Проверка |
|---|---|---|
| Хранение паролей | argon2id (m=19 МиБ, t=2, p=1), политика сложности | `apps/server/src/auth/passwords.ts`, интеграционные тесты auth |
| Перебор паролей | блокировка учётной записи после 10 ошибок на 15 мин, rate limit на `/auth/*` | `routes/auth.ts`, `AUTH_RATE_LIMIT_PER_MINUTE` |
| Второй фактор | TOTP RFC 6238; организация может требовать MFA | `auth/totp.ts`, `tests/unit/totp.test.ts` (эталонные векторы RFC) |
| SSO | OIDC (authorization code + PKCE через openid-client) | `auth/oidc.ts`; **с реальным IdP не проверялось** |
| Сеанс | случайный токен, в БД хранится только хеш; cookie `httpOnly`, `SameSite=Lax`, `Secure` в production; срок жизни `SESSION_TTL_HOURS` | `auth/sessions.ts` |
| CSRF | double-submit: cookie `kb_csrf` + заголовок `x-csrf-token` (сравнение за постоянное время) для всех изменяющих запросов | `app.ts` |
| WebSocket | проверка Origin, сессии и прав при подключении и при каждом изменении прав (`acl_epoch`) | `routes/collab.ts`, `collab/hub.ts` |
| Отзыв доступа | блокировка/увольнение отзывает сеансы и API-токены; открытые документы переходят в режим чтения или закрываются | интеграционные тесты ACL/collab |
| API-токены | префикс `kb_`, хранится хеш, срок действия, список и отзыв пользователем | `routes/admin.ts` |

## Авторизация

* Все проверки — на сервере (`acl/engine.ts`); UI только скрывает недоступное.
* Недоступные страницы — 404 (не раскрывается существование); поиск, дерево, обратные ссылки, хлебные крошки, вложения, экспорт фильтруются по правам **до** формирования ответа.
* Наследование с границами, явный запрет, гости не входят в «всю организацию», личные пространства недоступны администраторам без явной выдачи.
* Расширение аудитории требует подтверждения с предпросмотром, кто получит доступ.
* Экспорт и скачивание — отдельные права и политики пространства.

## Контент пользователей

* HTML (вставка, импорт) — санитизация по allowlist (`sanitize-html`), ссылки только безопасных схем (`sanitizeHref`: http/https/mailto/tel/относительные), `javascript:`/`data:` в ссылках отбрасываются.
* SVG — очищается от скриптов и обработчиков событий при загрузке.
* Файлы отдаются с `X-Content-Type-Options: nosniff`, `Content-Disposition`, CSP `default-src 'none'; sandbox` (PDF — без sandbox, но без скриптов и только для встраивания самим приложением: встроенный просмотрщик браузера отказывается работать в песочнице).
* Исполняемые файлы (PE/ELF/скрипты с shebang и маскировкой расширения) отклоняются; антивирус ClamAV подключается переменной `CLAMAV_HOST` (**в окружении разработки не проверен — демона нет**).
* Импорт ZIP: защита от zip-slip, абсолютных путей, символических ссылок, зашифрованных записей и «zip-бомб» (лимиты числа, размера, коэффициента сжатия).
* Mermaid рендерится с `securityLevel: 'strict'`; формулы — KaTeX без `trust`.
* CSP приложения: `script-src 'self'`, `frame-ancestors 'none'`, `frame-src` — только своё происхождение и разрешённые видеохостинги (YouTube-nocookie, RuTube, VK), `object-src 'none'`. Проверяется `tests/integration/security-headers.test.ts`.

## Аудит

Журнал `audit_events` — только добавление (триггер запрещает изменение/удаление), каждая запись содержит хеш предыдущей (канонический JSON). Проверка целостности: `npm run audit-verify` или «Администрирование → Журнал аудита → Проверить». Логируются входы, изменения прав, экспорт/скачивание, администрирование, восстановление, архивы.

## Данные и секреты

* Секреты только через переменные окружения (`deploy/env.example`); в репозитории секретов нет. В production сервер не стартует со слабым `SECRET_KEY`.
* Шифрование при хранении обеспечивается инфраструктурой (диск/СУБД/S3 SSE); резервные копии — с шифрованием (см. `BACKUP_RESTORE.md`).
* Корзина и сроки хранения, legal hold блокирует безвозвратное удаление.

## Известные ограничения (честно)

1. Внешние изображения во вставленном HTML загружаются браузером напрямую с внешнего адреса (CSP `img-src https:`); серверного прокси с защитой от SSRF нет. Риск — утечка факта просмотра внешнему серверу. Рекомендация: включить политику «копировать внешние изображения при вставке» после реализации прокси.
2. Нет независимого тестирования на проникновение и SCA в CI. Разбор `npm audit --omit=dev` (22.10.2026): react-router обновлён до 7.18.4 (open redirect устранён). Остались (moderate/low, без доступного исправления без смены мажорных версий): `uuid` внутри exceljs (уязвимость только для v3/v5/v6 с внешним буфером — не используется), `sprintf-js`/`argparse` внутри mammoth (CLI-зависимость, на вход не подаются пользовательские форматные строки), `katex` внутри remark-math на сервере (обход `trust` — `trust` не включается). Перед выпуском повторить разбор.
3. OIDC и ClamAV не проверены с реальными сервисами.
4. Ограничения rate limit — на экземпляр процесса, а не глобальные.
