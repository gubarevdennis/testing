# Готовность к выпуску

**Вердикт на 23.10.2026: продукт НЕ готов к промышленной эксплуатации.** Шлюз выпуска (`python3 scripts/release-gate.py`) не пройден. Функциональность реализована полностью по объёму ТЗ, без демонстрационных заглушек. Но часть обязательных (P0) критериев приёмки не доказана: в одних случаях по ним есть известные дефекты, в других доказательство невозможно получить в среде разработки (другие браузеры, реальные Word/OIDC/ClamAV/S3, второй сервер, пилот с сотрудниками). Ниже перечислено, что проверено и чем, что не выполнено и какие действия нужны, чтобы закрыть каждый пункт.

Документ составлен по фактическим прогонам. Повторить все цифры можно командами из раздела 7.

Что проверяется по областям, перечислено в `docs/TEST_MATRIX.md` (по каждому тесту — PASS/FAIL/BLOCKED со ссылкой на прогон и git-sha) и в `docs/UX_ACCEPTANCE.md`.

Главные свойства сохранности данных, подтверждённые тестами:

* «Сохранено» показывается только после подтверждения сервера, которое отправляется после фиксации транзакции в PostgreSQL. Правка не теряется при обрыве сети, убийстве процесса сервера, отказе БД и хранилища. Повтор идемпотентен.
* Офлайн-правки хранятся в IndexedDB, привязаны к пользователю и поколению документа и отправляются после подключения. Переполнение хранилища показывается как ошибка, а не как «сохранено».
* Конфликт «правка ↔ удаление/перенос» сохраняет копию версии пользователя. Неслиемые операции и смена схемы документа открывают диалог с тремя вариантами и не теряют локальные правки.
* История: восстановление статьи или блока создаёт новую версию и не стирает последующие; аудит неизменяем (хеш-цепочка, `npm run audit-verify`).
* Права: проверяются на сервере в API, WebSocket, поиске, экспорте, уведомлениях. Недоступное отдаётся как 404. Отзыв прав действует «на лету».

## 4. Резервное копирование и восстановление (`docs/BACKUP_RESTORE.md`, `docs/drills/`)

Учение 23.10.2026. Сценарий: потеряна вся площадка — каталог БД, живые файлы и локальный репозиторий копий. Восстановление шло только из зашифрованной второй копии (age) в новый кластер PostgreSQL и новый процесс приложения.

| Цель | ТЗ | Измерено |
|---|---|---|

| RPO, файлы | ≤ 5 мин | 27,8 с |
| RTO до работающего API | ≤ 60 мин | 5,9 с |
| RTO с проверками целостности | ≤ 60 мин | 7,5 с |

Проверки после восстановления: число строк 24 таблиц, sha256 всех файлов, байт-в-байт совпадающий экспорт страницы, цепочка аудита, права (посторонний получает 404).

Ограничение: «независимый сервер» — отдельный кластер на том же физическом хосте; объём — сотни МБ, а не 100 ГБ+. Шлюз выпуска падает, если протокол учения старше 31 дня или не укладывается в цели.

## 5. Дефекты, найденные и исправленные на финальной проверке

* Архив организации с файлами страниц из корзины не восстанавливался («В архиве нет файла undefined»). Это была потеря возможности восстановления. Исправлено, добавлен регрессионный тест.
* Миграция схемы документа записывала версию формата отдельной транзакцией. Сбой между транзакциями привёл бы к повторной миграции. Теперь версия пишется атомарно с содержимым.
* Боковая панель не знала открытую страницу (рендерится вне `<Routes>`): страница не выделялась, предки не раскрывались, дерево не прокручивалось к ней. Исправлено, добавлен тест.
* Скачивание файлов, похожих на gzip, отдавало повреждённые данные из-за сжатия ответов. Исправлено, добавлен тест.
* XSS через заголовок страницы в Markdown-экспорте; подмена IP через `X-Forwarded-For` (обход ограничения частоты входа и подделка адреса в аудите); ReDoS в импорте DOCX и поисковых синонимах. Исправлено, добавлены тесты.
* Секрет TOTP хранился открытым текстом; разрешались пароли короче 12 символов и распространённые пароли; не было тайм-аута простоя сеанса; production принимал ключ-заглушку. Исправлено по ASVS L2 (`docs/ASVS.md`).
* Дефекты интерфейса QA-D1…D8: 500 в списке пространств при гонке, двойное создание токена, «Переименовать» в меню дерева, вкладка настроек пространства, ошибка позиции в редакторе после вставки колонок, меню блока действовало на другой блок, подменю за краем экрана. Исправлены, каждый закрыт тестом.
* Быстрый переход (Ctrl+K) терял символы, набранные сразу после открытия. Исправлено.
* Касание на телефоне открывало подменю поверх нажимаемого пункта (браузер генерирует «мышиные» события после касания). Дерево прокручивалось виртуализатором в несколько кадров и спорило с прокруткой пользователя. Исправлено, сценарии покрыты тестами.

### 6.2 P0 в статусе «частично» (полный список — `python3 scripts/release-gate.py`)

* **Процесс QA (R-QA-*, QA26-*, R-PROCESS-018/053, R-UI-026/061/068, OPS-018).** Инструменты есть: инвентаризация, матрица действие × состояние, ввод результатов прогонов, реестр дефектов, шлюз. Но покрытие неполное: 35,6 % действий и 9,3 % ячеек действие × состояние. Действие: дописать тесты по матрице, прогнать `npm run qa:run` в CI на каждом коммите.
* **Браузеры и устройства (R-QA-014/019/032, AT-88, R-QA-017).** Автотесты идут только в Chromium (D-18). Действие: прогнать Playwright-проекты Firefox и WebKit на CI-агенте с этими браузерами, пройти ручной чек-лист `docs/UX_ACCEPTANCE.md` §3 на Edge, Safari macOS/iOS, Chrome Android и с экранными дикторами.
* **Пилот с сотрудниками (R-QA-033, R-UI-055, R-PROCESS-052).** Действие: провести сценарий `docs/UX_ACCEPTANCE.md` §2 (5–8 человек), затем тестовую эксплуатацию.
* **Права (R-ACL-026/046 — кеш эффективных прав; R-ACL-036 — выдача «участникам пространства X»).** Кеш намеренно не используется (D-24). Нужно согласовать с заказчиком, принимается ли это решение. Выдача пространству как субъекту требует доработки ACL-движка.
* **Редактор (R-EDITOR-038 — сноски; QA26-06/07 — выделение пальцем, пять контекстов для каждого действия; R-MEDIA-007 — встроенные в строку изображения; R-IMPORT-021 — единый конвейер буфера и импорта).** Действие: реализовать сноски вместе с повышением версии схемы контента (механизм миграции готов, D-26…D-30).
* **Иерархия (R-TREE-005).** Отдельного уровня «Workspace» между организацией и пространством нет. Требуется бизнес-решение: нужен ли он.
* **Эксплуатация (R-OPS-003/022).** Нет конвейера доставки (CD) и интеграции с менеджером секретов. Действие: подключить к корпоративному CI/CD и хранилищу секретов.
* **Отказоустойчивость и нагрузка (R-QA-005/021/034/037/038, QA26-20/25).** Fault injection, рандомизированные конкурентные тесты и нагрузка есть. Нет soak-теста на сутки, сценариев Wi-Fi/LTE и многоэкземплярного режима под нагрузкой. Действие: стенд из двух и более экземпляров, суточный прогон.

## 7. Как воспроизвести

```bash
npm ci
npm run typecheck && npx eslint . && npm run security:sast && npm run security:deps
npx vitest run                     # unit + integration + resilience (нужен PostgreSQL 16)
npm run test:e2e                   # собирает клиент в .e2e-web и запускает Playwright
npm run security:dast              # baseline DAST на изолированном сервере
npm run restore:drill              # учение аварийного восстановления (нужны postgresql-16 и age)
npm run qa:run                     # все тесты с JSON-отчётами → docs/TEST_MATRIX.md, docs/qa/*
python3 scripts/requirements/trace.py && python3 scripts/release-gate.py
```

Решение о выпуске принимается только при `RELEASE GATE: PASSED` и подписанных пунктах §6.3.
