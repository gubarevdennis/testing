## A. ПРАВИЛА ИСПОЛНЕНИЯ ДЛЯ CLAUDE CODE

1. **Сначала исследуй репозиторий:** структуру, текущую реализацию, стек, зависимости, миграции, API, UI, тесты, конфигурации, документацию, известные дефекты. Не переписывай исправно работающий код без причины. Если репозиторий пуст — создай поддерживаемую структуру проекта.
2. **Составь реестр требований:** каждому пункту настоящего ТЗ присвой ID, модуль, приоритет P0/P1/P2, статус, тесты и критерий приёмки. Сохрани `docs/REQUIREMENTS_TRACEABILITY.md`. Ни один пункт не должен исчезнуть из плана.
3. **Создай `docs/ARCHITECTURE.md`, `docs/DECISIONS.md`, `docs/TEST_MATRIX.md`, `docs/OPERATIONS.md`, `docs/RELEASE_READINESS.md`**. Технические решения принимай самостоятельно, объясняй компромиссы. Запрашивай уточнение лишь при действительно блокирующей бизнес-неоднозначности, критическом риске или необходимости секретов/доступа.
4. **Выполняй вертикальными срезами:** БД + сервер + API + интерфейс + права + тесты + диагностика. Не ограничивайся внешним видом без работающего хранения, не ограничивайся API без завершённого UX.
5. **После каждого среза:** запусти сборку, статический анализ, модульные и интеграционные тесты, браузерные E2E и визуальную проверку. Исправляй ошибки до перехода к следующему срезу.
6. **Обязательно тестируй в реальном браузере:** навигация, курсор, выделение, hover, кнопки, меню, drag-and-drop, масштаб, таблицы, мобильная адаптация, копирование/вставка, Undo/Redo, импорт/экспорт, права и восстановление. Одних unit-тестов недостаточно.
7. **Не скрывай ограничения:** если не удалось выполнить инфраструктурные или внешние испытания, укажи их как непроверенные блокеры. Не заявляй «production-ready» без свидетельств испытаний.
8. **Не удаляй функции для упрощения.** Если техническая библиотека не поддерживает требование, расширь её, замени или разработай корректное решение с тестами.
9. **Сохраняй исходные данные и обратную совместимость.** Любая миграция — с резервной копией, проверкой и откатом.
10. **Отчёт по итогу:** перечень реализованного, трассировка требований, команды запуска, результаты тестов, дефекты, производительность, резервирование, ограничения и точная инструкция эксплуатации.

## B. ИЕРАРХИЯ ТРЕБОВАНИЙ И РАЗРЕШЕНИЕ КОЛЛИЗИЙ

- Этот раздел A–L и согласованная финальная продуктовая философия имеют приоритет над устаревшими фразами в сохранённом историческом корпусе ниже.
- **Форматы:** обязательны DOCX и Markdown import/export, CSV/XLSX для таблиц, PDF и HTML как экспорт, ZIP полного переносимого архива. PDF как редактируемый импорт не обязателен. Раннее исключение PDF/HTML из экспорта считать отменённым.
- **Глубина вложенности:** пользовательская модель произвольная; ранний лимит API 15 уровней не должен превращаться в UX-ограничение. Технический лимит допускается только если доказан и не мешает реалистичным структурам; предпочтительны алгоритмы без жёсткой глубины.
- **Доступ:** пространства и группы — первичный уровень; постраничные ACL — редкие явные исключения. Никогда не заставляй пользователя выбирать права при обычном создании статьи.
- **Синхронизация:** не навязывать исключительно WebSocket. Критерий — устойчивое, без потерь, многопользовательское редактирование и восстановление после обрывов. CRDT/OT выбирается по проверенным свойствам.
- **UI:** светлый, минималистичный, сдержанный, соответствующий показанным согласованным интерактивным макетам. Это не 3R Warehouse и не тёмный фирменный UI.
- **История и резервирование:** сохранять максимальные из согласованных гарантий, не упрощать ради скорости.
- **Слова «всё протестировано» означают доказанное покрытие каждого доступного элемента и пользовательского действия**, а не буквальный перебор математически бесконечных последовательностей. Используй каталог состояний, матрицы переходов, pairwise, property-based и риск-ориентированные комбинаторные тесты.

## C. ЦЕЛЕВОЙ ПРОДУКТ И ПОЛЬЗОВАТЕЛЬСКАЯ ФИЛОСОФИЯ

**Внешне:** максимально простой, эстетичный, быстрый, интуитивный инструмент уровня Notion по ощущению. **Внутри:** функционально богатая, защищённая, транзакционная, восстановимая, наблюдаемая корпоративная платформа. Пользователь должен думать о работе, а не о настройках интерфейса.

- Минимизируй обязательные диалоги и количество кликов; используй умные контекстные действия, наследование настроек и понятные значения по умолчанию.
- Предугадывай следующий шаг: `+` рядом с разделом создаёт дочернюю страницу с фокусом в заголовке; таблица сама переносит текст; меню остаётся в пределах экрана; последний контекст навигации восстанавливается.
- Сохраняй выделение, курсор, прокрутку, состояние дерева, открытые вкладки и данные при ререндере, навигации, синхронизации и сетевых сбоях.
- Все операции обратимы там, где это возможно; опасные действия сопровождаются точным предпросмотром последствий, но не бесконечными подтверждениями.
- Действия мышью, клавиатурой и на телефоне должны быть одинаково доступны в пределах возможностей платформы.
- Не допускать обрезаний, перекрытий, случайного скролла, прыжков layout, дрожания, ложных состояний «сохранено» и скрытой утраты данных.

## D. ОБЯЗАТЕЛЬНЫЕ РОЛЕВЫЕ МАРШРУТЫ

**Сотрудник:** войти → увидеть только свои пространства → открыть регламент → поиск → создать статью внутри отдела одной кнопкой → редактировать/форматировать → вставить Excel-таблицу/изображение → поделиться ссылкой в пределах прав → выйти и вернуться без потерь.

**Автор:** создать личный черновик → работать офлайн → синхронизировать → перенести в пространство отдела с предпросмотром изменения видимости → отправить на согласование → опубликовать → обновить и откатить версию.

**Руководитель пространства:** структурировать дерево drag-and-drop → настроить шаблоны → управлять участниками и доступом группы → контролировать публикации → восстановить удалённую ветку.

**Администратор:** создать подразделение/группу → добавить сотрудника → автоматически выдать доступ к пространству → пригласить гостя только в раздел на срок → приостановить пользователя → отозвать сессии → увидеть объяснение эффективных прав → проверить аудит и резервные копии → восстановить тестовый экземпляр.

**Два редактора:** одновременно правят один абзац, таблицу и структуру → связь у одного пропадает → оба продолжают → связь восстанавливается → никакой подтверждённый текст не теряется, история остаётся связной.

**Аудитор:** проверить кто и когда изменил документ, права, удаление, импорт, восстановление, не получив скрытого доступа к посторонним материалам.

## E. ПРИЁМОЧНЫЕ ИНВАРИАНТЫ СОХРАННОСТИ

- **E-01** Подтверждённые сервером изменения не теряются при обычных отказах приложения.
- **E-02** Локальные неподтверждённые изменения сохраняются в устойчивой очереди в поддерживаемых браузерных условиях, статус виден пользователю.
- **E-03** Повторная/переупорядоченная доставка операций не дублирует и не стирает данные.
- **E-04** Одновременные изменения не перезаписываются молча; конфликт сохраняет данные и объясним пользователю.
- **E-05** Перенос, удаление, восстановление дерева и изменение ACL атомарны или имеют гарантированную компенсацию.
- **E-06** Все внутренние ссылки используют стабильные ID и переживают переименование и перенос.
- **E-07** Удаление обратимо через корзину и версии в пределах политики хранения.
- **E-08** Бэкап подтверждён только успешным восстановлением и проверкой контрольных сумм.
- **E-09** Импорт не повреждает существующие материалы, поддерживает dry-run и безопасный повтор.
- **E-10** Полный архив пригоден для чтения без приложения и обратного импорта.
- **E-11** Права одинаково применяются к документу, поиску, вложению, истории, экспорту, API, уведомлениям и кешу.
- **E-12** При отзыве прав не остаётся работающих прямых ссылок/активных сессий, раскрывающих запрещённые данные.
- **E-13** UI не утверждает «сохранено», пока нет достаточного подтверждения устойчивой фиксации.
- **E-14** Обновления приложения и миграции имеют воспроизводимый откат.

## F. МАТРИЦА ПРОВЕРОК И КАЧЕСТВА КАЖДОГО ЭЛЕМЕНТА

Для каждого компонента перечисли все состояния: default, hover, focus, active, disabled, loading, error, empty, overflow, mobile, zoom 200%, keyboard, screen-reader. Прогони браузерную матрицу на 320/375/768/1024/1440/1920px, zoom 200%, мышь/клавиатура/сенсор; Safari/WebKit, Chromium, Firefox в пределах доступных окружений. Делай визуальные скриншоты эталонных экранов и сравнение регрессий.

**UX-сравнение с Notion:** одинаковые повседневные задачи, количество кликов, время, ошибки, субъективная оценка. Не копировать чужие ассеты и исходники. Цель — отсутствие существенного проигрыша по удобству ключевых действий, при превосходстве по контролю сохранности.

# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Корпоративная база знаний и профессиональный редактор документов
**Версия:** 1.7 · **Дата:** 22.10.2026 · **Статус:** базовое ТЗ для проектирования, реализации и приёмки

> **Продуктовая цель:** создать самостоятельную корпоративную базу знаний с удобством современных wiki-систем (Notion, Confluence, Outline), сильным WYSIWYG-редактором, двусторонним импортом/экспортом DOCX и Markdown (.md), надёжным копированием, распознаванием текста на изображениях, совместным редактированием, поиском, версионностью и управлением доступом. Копирование возможностей означает функциональную эквивалентность, а не воспроизведение чужих интерфейсов, кода и фирменных материалов.

## 1. Границы проекта

### 1.1. Включено
- Организации/рабочие пространства; пространства знаний; древовидные разделы, папки и страницы.
- Профессиональный блочный редактор, форматирование, таблицы, изображения, код, схемы, ссылки, вложения и интерактивные элементы, перечисленные далее.
- Совместная работа, комментарии, упоминания, согласование и публикация страниц; история и восстановление.
- Импорт и экспорт документов **DOCX и .md**, а также импорт **CSV и XLSX в табличные блоки/коллекции**; при работе с Markdown поддерживается пакетный ZIP с .md и связанными медиафайлами. PNG/JPG/WebP/SVG рассматриваются как медиа/вложения, но не самостоятельные форматы импортируемых документов.
- Копирование контента в буфер как text/plain и text/html, командой «Копировать Markdown», плюс копирование блоков, разделов и ссылок.
- OCR для изображений и скриншотов, включая русский и английский язык; сохранение исходника и проверяемого результата.
- Поиск, версии, права, аудит, резервное копирование, импорт/экспорт, администрирование, API.

### 1.2. Исключено
- CRM, управление задачами, канбан, тайм-трекинг, склад, закупки, финансы, мессенджер, почтовый клиент и универсальная платформа бизнес-процессов; структурированные табличные коллекции для базы знаний входят в проект.
- Полноценный настольный Word и пиксель-в-пиксель восстановление сложной вёрстки Word; базой знаний управляет собственная семантическая структура контента.
- PDF, HTML и ODT как пользовательские форматы импорта/экспорта документов в рамках этой версии; XLSX поддерживается для импорта табличных данных, не как универсальный редактор Excel. HTML допустим внутри буфера обмена и движка рендеринга.
- Обязательная генерация контента с помощью внешнего ИИ. OCR обязателен, интеллектуальные подсказки — отдельный опциональный модуль.

### 1.3. Целевые пользователи
- Читатель: ищет знания, читает, копирует, скачивает по разрешению.
- Автор: создаёт черновики, редактирует, загружает документы и изображения.
- Редактор: структурирует и актуализирует материалы, управляет публикацией своего пространства.
- Владелец пространства: назначает участников и шаблоны, управляет структурой.
- Администратор организации: SSO, политики, пользователи, журналы, резервное копирование.
- Аудитор: просматривает доступные ему версии, публикации и журнал действий, не редактируя контент.

## 2. Информационная архитектура и модель сущностей
- `Organization` → `Workspace` → `Space` → `Page`, где страница допускает неограниченную вложенность, определённый API-лимит глубины 15 и возможность изменения уровня без потери ссылок.
- Страница: `id` (неизменный UUID), название, slug, обложка, иконка, блоки контента, статус, владелец, автор, время изменения, теги, версия, права, публикация, связи, вложения, OCR-текст.
- Статусы: черновик → на согласовании → опубликовано → архивировано. Возврат на доработку доступен; отдельные рабочие пространства могут отключить обязательное согласование.
- Типы связей: родитель–дочерняя, обычная ссылка, обратная ссылка, упоминание, вложение, якорь блока, связанная страница.
- Иерархия не должна заменять полнотекстовый поиск. У каждой страницы постоянный URL по ID/slug; изменение имени и перенос не разрывают ссылки.
- Удаление по умолчанию — мягкое, с корзиной и восстановлением (90 дней, настраивается); окончательное удаление по политике и при наличии права.
- Шаблоны — обычные страницы с параметрами-заполнителями, версионируемые отдельно.

### 3.2. Экран страницы
- Заголовок, хлебные крошки, автор/обновление, статус, метки, действия «Поделиться», «Копировать», «Экспорт», «История», «…».
- Режим чтения — чистый и быстрый; режим редактирования — WYSIWYG без отдельной «сырой» формы.

- Для малых экранов: дерево в выдвижной панели; действия доступные с клавиатуры; таблицы с горизонтальной прокруткой; одинаковая семантика функций без необъяснимых исчезновений.

## 4. Редактор: требования к полноте

### 4.1. Базовые текстовые элементы
- Параграф, заголовки H1–H6, вводный текст, цитаты, разделитель, типографские переносы.
- Жирный, курсив, подчёркнутый, зачёркнутый, надстрочный и подстрочный, `inline code`, цвет текста и фона, выделение маркером.
- Нумерованные, маркированные, многоуровневые списки, чек-листы с настоящим состоянием выполнено/не выполнено.
- Ссылки (название/URL), внутристраничные якоря, ссылки на страницы, упоминания сотрудников, теги.
- Клавиатурные сочетания, отмена/повтор, множественное выделение, доступное контекстное меню.

### 4.2. Блочные элементы
- Таблицы: вставка/удаление строк и столбцов; перемещение; изменение ширины; выравнивание; объединение/разделение ячеек; заголовок таблицы; выделение диапазона; копирование табличного диапазона; вставка из Excel как таблицы; сортировка простых таблиц.
- Callout/предупреждение/примечание/успех с иконкой и цветом по смыслу; раскрывающийся блок (toggle); панель с вкладками — необязательная, если нарушает переносимость.
- Блок кода с языком, подсветкой и кнопкой «Копировать»; режим без выполнения произвольного кода.
- Изображения с подписью, alt-текстом, размером, выравниванием, увеличением, заменой; галерея при необходимости.
- Вложения как безопасные ссылки для скачивания с названием и размером; ссылка-превью; встроенное содержание другого документа по постоянной ссылке (без дублирования данных).
- Простые схемы Mermaid как редактируемый исходный текст с безопасным превью; при экспорте DOCX — изображение плюс доступ к исходнику, при экспорте Markdown — исходный fenced-блок.
- Оглавление, автоматически строящееся по заголовкам, и блок «Связанные страницы».
- Математические формулы LaTeX inline/block как отдельная расширяемая функция.

### 4.3. Редакторские взаимодействия
- `Enter` создаёт ожидаемый тип блока; `Shift+Enter` — перенос строки; `Tab/Shift+Tab` — вложенность списка или переход по таблице согласно контексту.
- `/` открывает поиск доступных блоков, команда по названию и синонимам; `@` — упоминания; `[[` — ссылки на страницы.
- Плавающая панель при выделении, блоковый `+` и drag-handle, доступный через клавиатуру аналог drag-and-drop.
- Быстрое перемещение блоков, дублирование, преобразование типа, копирование блока, раскрытие/сворачивание секций.
- Вставка изображений перетаскиванием, из буфера и через диалог файла; ясный прогресс загрузки.
- Корректная работа с IME, кириллицей, русскими кавычками, emoji, длинными URL и текстом 100 000+ символов.
- Выделение и курсор не должны прыгать при автосохранении или совместном редактировании.

## 5. Буфер обмена: критический пользовательский контракт

### 5.1. Явные действия
На странице и в контекстном меню должны существовать: «Копировать выделение», «Копировать страницу с форматированием», «Копировать как обычный текст», «Копировать Markdown», «Копировать ссылку на страницу», «Копировать ссылку на блок», «Копировать таблицу», «Копировать код».

### 5.2. Поведение
- Обычные `Ctrl/Cmd+C` и `Ctrl/Cmd+V` работают без перехвата в неуместном контексте; выделенный текст не теряется.
- По команде «с форматированием» записать минимум `text/plain` и `text/html` с безопасным HTML; вставка в Word/почту и редактор должна сохранять H1–H6, списки, жирный/курсив, ссылки, таблицы и изображения там, где целевое приложение это поддерживает.
- По команде «Markdown» копировать корректную UTF-8 строку со структурой заголовков, списков, таблиц, ссылок и code fences.
- Копирование таблицы — также TSV (`text/plain`) для вставки в табличные приложения; копирование кодового блока — только исходный код, без кнопок и номеров строк.
- Копирование изображения: оригинал либо URL согласно правам и браузерным ограничениям; отказ в доступе не превращается в «пустую успешную операцию».
- Результат копирования подтверждать коротким уведомлением только после успешной записи в clipboard; при запрете Clipboard API предлагать выделяемый текст и штатное копирование.
- Вставка внешнего HTML проходит санитизацию; варианты «Сохранить форматирование», «Объединить форматирование», «Вставить только текст» доступны по ситуации.
- После вставки из Microsoft Word, Google Docs, веб-страницы и другого экземпляра продукта не должны появляться исполняемые скрипты, мусорная разметка или потерянные табличные ячейки.
- В мобильных браузерах предоставить альтернативы clipboard-функциям, запрещённым платформой; нельзя обещать одинаковые системные возможности там, где ОС их ограничивает.

## 6. Импорт DOCX и Markdown

### 6.1. Интерфейс
- Drag-and-drop одного или нескольких файлов; выбор через диалог; предпросмотр; указание целевого раздела; выбор режима «новая страница» / «новая дочерняя страница» / «обновить существующую с созданием версии».
- Показать обнаруженные заголовки, количество блоков/таблиц/изображений, предупреждения о неподдержанных конструкциях; дать возможность отменить до публикации.
- Массовый импорт .md, .docx, ZIP с Markdown и локальными вложениями; защита от ZIP-bomb и небезопасных путей.

### 6.2. DOCX
- Извлечь: заголовки, текст, inline-стили, списки/вложенность, таблицы/объединение ячеек, гиперссылки, изображения, подписи, разделители, базовые колонтитулы/сноски в виде переносимых блоков или заметок.
- Сохранять исходный файл отдельно как артефакт импорта, если политика разрешает; контент конвертировать в каноническую внутреннюю модель.
- Для сложных фигур, SmartArt, плавающих объектов, полей и нестандартных шаблонов — конвертировать в изображение или выводить отчёт о частичной совместимости; **молчаливая потеря запрещена**.
- Отключить выполнение макросов и внешних связей; запрещать активный/вредоносный контент.

### 6.3. Markdown
- Поддерживать CommonMark и GitHub Flavored Markdown: заголовки, параграфы, списки, task lists, blockquote, tables, code fences, изображения, ссылки.
- Для изображений и относительных ссылок разрешать путь лишь внутри загружаемого ZIP/выбранной папки; сохранять вложения и переписывать ссылки на постоянные внутренние URL.
- YAML front matter извлекать в метаданные только по явной схеме; неизвестные поля сохранять безопасно без потери в отчёте.
- Для недоступных ссылок и файлов формировать предупреждение, а не удалять ссылку бесследно.
- Документы с частично несовместимыми конструкциями должны импортироваться с отчётом и обратимой копией оригинала.

## 7. Экспорт DOCX и Markdown

### 7.1. DOCX
- Экспорт одной страницы, ветки и выбранного набора страниц; каждую страницу — отдельным DOCX или в общем документе с оглавлением по выбору.
- Стили Word Heading 1–6, нормальный текст, списки, табличные структуры, hyperlinks, медиа, подписи, код (моноширинный шрифт), указание авторства и даты версии при необходимости.
- Результат должен открываться без ошибок в Microsoft Word и LibreOffice, а структура документа должна быть доступна для дальнейшего редактирования.
- Mermaid и нестандартные блоки: изображение/текстовая альтернатива и запись о конвертации; обязательный отчёт при потере семантики.

### 7.2. Markdown
- Экспорт `.md` как UTF-8, LF, GFM. Для встроенных изображений/файлов — ZIP с `index.md` и папкой `assets/`; относительные пути корректны после распаковки.
- Для одной страницы без вложений — прямое скачивание `.md`; с вложениями — ZIP или режим «Markdown со ссылками на сервер» с явным предупреждением о зависимости от доступа.
- Поддерживать копирование Markdown в буфер без предварительного скачивания.
- Сложные таблицы (объединённые ячейки, несколько блоков в ячейке), комментарии и ACL не представимы обычным GFM: требовать режим совместимости и уведомлять о преобразовании; внутренний оригинал не изменяется.
- Экспорт строго под правами `export`, в том числе при пакетных операциях и ссылках на вложения.

### 7.3. Формальная матрица преобразований
| Конструкция | DOCX импорт/экспорт | MD импорт/экспорт | Правило |
|---|---|---|---|
| Заголовки, стили, списки, ссылки | Да/Да | Да/Да | Семантическое сохранение |
| Простые таблицы | Да/Да | Да/Да | Сохранение ячеек |
| Объединённые ячейки | Да/Да | Ограниченно | Явный отчёт о деградации |
| Изображения | Да/Да | Да/Да (assets) | Без потери оригинала |
| Код | Да/Да | Да/Да | Язык и содержимое сохраняются |
| Toggle, callout | Адаптация | Адаптация | Контент не пропадает |
| Mermaid | Изображение + исходник | Исходник | Редактируемость исходника |
| Комментарии, версии, права | Не входят в переносимый контент | Не входят в переносимый контент | Только в системе / отдельно в аудите |

## 8. OCR и работа со скриншотами
- На изображении: «Распознать текст», «Скопировать распознанное», «Вставить текст в документ», «Найти по тексту», «Повторить распознавание».
- Источники: вставка из системного буфера, drag-and-drop, медиа в DOCX, прикреплённые PNG/JPEG/WebP, скриншоты.
- Языки: русский, английский, смешанный текст, цифры, латиница, кириллица; отдельно проверить инженерные обозначения, таблицы и кодовые фрагменты.
- Результат: текст, уверенность и координаты текстовых фрагментов; отображать подсветку на исходной картинке, допускать ручную правку и фиксировать исправленный вариант.
- Область распознавания (crop/selection) и поворот изображения; повторный запуск при выбранном языке.
- OCR не должен замещать оригинал: хранить исходное изображение, автоматическое распознавание и ручную коррекцию отдельными данными.
- Индексировать OCR-текст с отметкой происхождения; в выдаче показывать, что совпадение найдено «на изображении».
- Для документов только DOCX/.md: OCR — сервис обработки медиа, а не заявка на импорт PDF или офисных форматов вне области проекта.
- Статус OCR — «ожидает», «обрабатывается», «готово», «частично», «ошибка»; очереди, повторы и контроль времени.
- Опционально: интеллектуальная структуризация распознанной таблицы с обязательной проверкой человеком перед заменой изображения таблицей.

## 9. Поиск, навигация и знаниевая связность
- Глобальный поиск по названиям, содержимому, заголовкам, тегам, комментариям (если у ищущего есть право), подписям, именам файлов, OCR-тексту.
- Полнотекстовый поиск по RU/EN, лемматизация/стемминг, опечатки, подсветка фрагмента, варианты слов, фильтры по пространству, автору, дате, типу и статусу.
- Быстрый поиск по команде `Ctrl/Cmd+K`, клавиатурная навигация результатами, переход к конкретному совпадению внутри страницы.
- Оглавление страницы, breadcrumbs, обратные ссылки, «связанные материалы», ссылки на блоки.
- Права применяются **до выдачи** результатов, сниппетов, автодополнения, счётчиков и API. Недоступные названия и фрагменты не должны просачиваться.
- Перемещение/переименование и массовое обновление не ломают ссылки и поисковый индекс.

## 10. Совместное редактирование и комментарии
- Одновременное редактирование одной страницы несколькими пользователями с видимыми курсорами, выделениями и статусом присутствия.
- Изменения распространяются без необходимости перезагрузки страницы; при потере сети локальные изменения остаются и синхронизируются при восстановлении.
- При конкурентных правках применить CRDT или эквивалент с формально проверяемой сходимостью; нельзя принимать схему «последний сохранивший затёр всех».
- Комментарии к выделению и блоку; ветки ответов; `@mention`; «разрешить»/«переоткрыть»; привязка к версии и к стабильному ID блока.
- Режим предложений правок — после базовой коллаборации, но до признания продуктовой полноты; решение принимать/отклонять требует роли редактора.
- При одновременном восстановлении старой версии создать **новую** версию, не стирая историю.
- Риск конфликтов при смене схемы документа, копировании блока и отключённой сети покрыть интеграционными тестами.

## 11. Процесс публикации и управление актуальностью
- Страница как черновик, запрос согласования, назначение согласующего, замечания, публикация и отзыв публикации.
- Опциональные свойства: ответственный за содержание, дата пересмотра, тип материала, критичность, подразделение, продукт/проект, срок действия.
- Страница с истёкшим сроком проверки помечается как «Требует актуализации», но не удаляется автоматически.
- Шаблоны: регламент, инструкция, база решений, FAQ, паспорт продукта, техническое описание, протокол, чек-лист, инструкция по тестированию, onboarding.
- Просмотр «Что изменилось» для конкретной версии: автор, дата, изменения текста/блоков; идентификатор опубликованной редакции.
- Напоминания об актуализации и упоминания без превращения продукта в полноценный task tracker.

## 12. Права доступа, безопасность, аудит
- RBAC минимум: системный администратор, владелец пространства, редактор, автор, читатель, аудитор; разрешения `view`, `create`, `edit`, `comment`, `publish`, `delete`, `manage_members`, `export`, `audit`.
- ACL наследуются от пространства и родительской страницы, поддерживают явно заданные исключения с понятным предпросмотром эффективных прав; **по умолчанию закрыто**, публичные ссылки выключены.
- Учётные записи: локальная аутентификация с MFA или корпоративный SSO (OIDC/SAML в зависимости от среды), сессии, отзыв доступа и принудительный logout.
- Сервисы применяют права на уровне API, объектов, вложений, версий, поискового индекса, OCR, экспорта и WebSocket-каналов, не только в UI.
- Журнал аудита: вход, отказ, просмотр/скачивание по политике, изменение, публикация, права, импорт/экспорт, удаление/восстановление, настройки; actor, time UTC, IP/session, action, target, outcome, correlation ID.
- Защита: TLS, шифрование на хранении, безопасное управление секретами, CSRF/XSS/SSRF, лимиты запросов, CSP, антивирусная и типовая проверка вложений, запрет обхода пути в архивах, HTML sanitize, исключение опасных ссылок.
- Контент и загруженные файлы не уходят во внешние OCR/AI API без отдельного административного включения, договора и видимого пользователю указания.
- Все внешние зависимости, в особенности платные компоненты редактора и конвертера, лицензируются и фиксируются до разработки. Нельзя случайно поставить закрытый модуль и сделать корпоративный продукт юридически зависимым без решения владельца.

## 13. История, автосохранение, удаление, резервные копии
- Автосохранение в фоне с явным статусом «Сохранено»/«Синхронизация»/«Ошибка»; потеря фокуса не должна удалять несохранённые правки.
- История документа: адресуемые серверные снимки после публикации, ручного сохранения, импорта и по интервалу (например, каждые 5 минут активного редактирования).
- Сравнение двух версий: вставлено/удалено/перемещено/изменено; восстановление как новый коммит в историю.
- Корзина с восстановлением, защита от случайного удаления пространства, подтверждение опасных административных операций.
- Бэкапы: ежедневные полные, инкрементальные/журналы по настройке, отдельное защищённое хранилище, шифрование, мониторинг успешности, регулярный тест восстановления.
- Цели: RPO не более 15 минут, RTO не более 4 часов для согласованного типового инцидента; эти показатели подтверждаются испытаниями инфраструктуры, а не только заявлениями.
- Экспорт резервной копии должен содержать не только страницы, но и структуру, медиа, ACL, версионность, связи и метаданные в документированном архивном формате.

## 14. Требования к визуальному стилю и анимациям
- Характер: современный деловой продукт; чистая типографика, глубокие нейтральные поверхности, комфортная плотность, лаконичные иконки, различимые интерактивные состояния. Не копировать пиксель-в-пиксель чужой дизайн.
- Цвет темы настраивается на уровне бренда и личных предпочтений; тёмная и светлая темы одинаково проработаны. Цвет не единственный носитель смысла.
- Система размеров: 8-пиксельная базовая сетка, последовательные отступы, не менее 3 уровней текстовой иерархии, контролируемая ширина чтения и адекватная ширина таблиц.
- Анимации функциональны: открытие контекстных меню 100–160 мс; боковых панелей 160–240 мс; перетаскивание 120–200 мс; индикатор сохранения без постоянного движения. Эти числа — ориентиры дизайна, а не оправдание блокировок ввода.
- `prefers-reduced-motion`: свести анимации к минимуму; интерактивные элементы не должны прыгать, смещать курсор или ухудшать доступность.
- Отдельно спроектировать hover, focus-visible, active, disabled, pending, success, error и пустые состояния **каждого** элемента управления.
- Доступность: целевой уровень WCAG 2.2 AA; управление клавиатурой, экранные дикторы, aria-label, контраст, табуляция, без зависимых от цвета сигналов.

## 15. Производительность, масштабирование, эксплуатация
- Стартовый ориентир: 10–200 сотрудников, 100 000 страниц, 500 000 вложений; рост без принципиальной переработки модели.
- Целевой p95: открытие типовой страницы до 2 секунд на корпоративной сети; реакции локального редактирования до 100 мс; запрос поиска до 1 секунды при прогретом индексе; навигация дерева до 300 мс. Измерять под заданной нагрузкой и на описанном оборудовании.
- Типовая страница: до 5 000 блоков; крупные страницы — виртуализация / частичная отрисовка, отсутствие блокировок основной нити.
- Импорт/экспорт больших документов (например 50 МБ) — фоновые задания с прогрессом, таймаутом, возможностью отмены и безопасными повторами.
- Доступность сервиса: целевой SLA 99,9% в месяц, кроме согласованного технического обслуживания; метрики внешним мониторингом.
- Логи, метрики, трассировка, health/readiness probes, алерты по sync, OCR, импортам, поисковому индексу, бэкапам; correlation IDs.
- Поддерживаемые браузеры: актуальные и две предыдущие основные версии Chrome, Edge, Firefox, Safari (desktop), Safari iOS и Chrome Android с документированными платформенными исключениями.

## 16. Предпочтительная архитектура (может быть заменена при равном качестве)
- Web-клиент: React + TypeScript, модульный UI и семантический WYSIWYG-редактор на ProseMirror/Tiptap.
- Сервер: TypeScript (NestJS) либо Python (FastAPI) — один основной API-контур с явными модулями и контрактами, без микросервисов ради микросервисов.
- PostgreSQL для пользователей, ACL, страниц, блоковых JSON-снимков, метаданных, аудита, связей; object storage S3-compatible для оригиналов/медиа/архивов.
- Redis или сопоставимая инфраструктура для очередей и временных состояний; OpenSearch или эквивалентный движок для поиска с фильтрацией прав.
- Совместное редактирование: Yjs (CRDT) + свой WebSocket-сервер/Hocuspocus либо лицензированный поддерживаемый сервер, **обязательно** с серверной долговременной записью обновлений и периодическими снапшотами.
- OCR-воркер: локальный PaddleOCR или сопоставимая модель, прошедшая тесты RU/EN на собственном наборе скриншотов; очередь и контроль доступа к медиа.
- DOCX: отдельный конвертер с двусторонним отображением в каноническую схему; Mammoth пригоден как часть семантического импорта, но **не обеспечивает сам по себе** высокоточный двусторонний обмен; экспорт реализовать и испытать отдельно.
- Markdown: парсер/сериализатор с собственной поддержкой нестандартных блоков и round-trip тестами; важно учитывать ограничения GFM и зрелость выбранной библиотеки.
- Источник истины: одна версионируемая семантическая схема документа (`schemaVersion`); HTML — представление, DOCX и MD — форматы обмена, а не первичное хранилище.
- Сервисные границы: `Auth`, `Spaces`, `Pages`, `EditorDocument`, `Permissions`, `Search`, `Media`, `OCR`, `ImportExport`, `Collaboration`, `Audit`, `Notifications`, `Backups`.
- API: REST/OpenAPI + WebSocket для живого редактирования; идемпотентные операции импорта, мутаций и экспорта с проверкой прав. Миграции схемы обратимо планируются и тестируются.
- Контур развёртывания: Docker Compose для локальной разработки, production в корпоративной инфраструктуре с HTTPS, секретами, мониторингом, резервным копированием и CI/CD; внешние SaaS не являются обязательной зависимостью.

## 18. Приёмочные сценарии (обязательная автоматизация E2E)

### А. Работа со страницами
1. Создать организацию, пространство, вложенную страницу, переименовать, перенести, восстановить из корзины — неизменный адрес ID и рабочие ссылки.
2. Создать страницу из каждого шаблона, отредактировать и опубликовать; другой читатель видит только опубликованное, если так задана политика.
3. Проверить работу дерева клавиатурой, мышью, drag-and-drop и на мобильном экране.
4. Создать документ 5 000 блоков и длинную таблицу без скачков курсора и потери ввода.

### Б. Редактор и копирование
5. Применить все inline-форматы, заголовки, вложенные списки, чек-листы, callout, toggle, формулы, ссылки, код и цитаты; сохранить/открыть — структура идентична.
6. Вставить из Word и веб-страницы текст с заголовками, таблицами, ссылками, картинками; проверить предпросмотр и отсутствие мусорной HTML-разметки.
7. Копировать выделение из базы и вставить в Word, почту, Google Docs и обратно — семантически сохраняются списки, ссылки и таблицы в пределах возможностей целевого приложения.
8. Нажать «Копировать Markdown» для страницы; вставить в текстовый редактор — корректный Markdown, UTF-8, code fences и таблицы.
9. Копировать таблицу в Excel/Sheets — исходные значения попали в правильные столбцы/строки; код — без UI-надписей.
10. При запрете clipboard браузером пользователь видит точное объяснение и альтернативный путь, а не ложное «Скопировано».
11. Проверить undo/redo после вставки, перемещения блока и изменения таблицы; фокус и выделение сохраняются.
12. Вставить потенциально вредоносные HTML/URL/SVG и убедиться, что произвольный JS не выполняется.

### В. DOCX и Markdown
13. DOCX с заголовками, 3 уровнями списков, ссылками, двумя таблицами, изображениями и кодом → импорт → правка → DOCX-экспорт → Word/LibreOffice: без пропажи контента.
14. DOCX с объединёнными ячейками импортируется с корректной структурой; если элемент не поддерживается, показан конкретный отчёт.
15. MD с GFM-таблицей, task list, кодом, относительными изображениями → импорт ZIP → экспорт ZIP → локальное открытие: пути рабочие.
16. Проверить MD round-trip parse→edit→serialize→parse на автоматическом наборе: не пропадают поддерживаемые элементы.
17. Для таблицы с объединением ячеек экспорт в MD уведомляет об ограничении; исходная страница не меняется.
18. Массовый импорт из 100 документов даёт список успешных/ошибочных файлов и позволяет повторить только неудачные.
19. Повреждённый DOCX, файл с ложным MIME, вредоносный ZIP и слишком большой файл отвергаются безопасно и объяснимо.
20. Импорт и экспорт проверяют права редактора/читателя; неизвестный пользователь не получает исходник по URL задания.

### Г. OCR
21. Русский скриншот с таблицей, английским текстом и артикулом → OCR → выбор фрагмента → копирование → вставка как текст.
22. У результата видны оригинал, confidence, исправления и происхождение текста; OCR-ошибка не удаляет изображение.
23. Поиск термина, присутствующего только на скриншоте, возвращает страницу с пометкой «совпадение в изображении».
24. Поворот, низкое качество, смешанный язык и выделенная область не ломают сервис; ошибку можно повторить.

### Д. Совместная работа и надёжность
25. Два автора одновременно редактируют один параграф и таблицу: оба видят изменения, после синхронизации документы одинаковы.
26. Отключить сеть на одном клиенте, изменить страницу, изменить её на другом, восстановить сеть: нет бесшумной потери данных, сходимость достигнута.
27. Отменить изменения одним пользователем; действия второго не откатываются ошибочно.
28. Восстановить старую версию — появилась новая ревизия, история не стёрта.
29. Удалить страницу, найти в корзине, восстановить; проверить права, вложения, внутренние ссылки.
30. Сымитировать сбой БД/объектного хранилища и восстановление из бэкапа: достигнуты целевые RPO/RTO на тестовом контуре.

### Е. Безопасность и UX
31. Читатель без доступа не видит страницу в поиске, подсказках, ссылках, API, файлах, истории и WebSocket.
32. Смена роли действует на открытый редактор без возможности продолжать запрещённые изменения.
33. Попытки XSS/CSRF/SSRF/path traversal/ZIP-bomb/загрузка исполняемых файлов блокируются на серверной стороне.
34. Полностью пройти интерфейс без мыши; читаются метки всех кнопок и ошибок; соблюдается контраст и reduced motion.
35. Пройти Chrome/Edge/Firefox/Safari, macOS/Windows, мобильные Safari/Chrome и матрицу Ctrl/Cmd+С/V, вставки изображений и DOCX/MD скачивания.
36. На медленной сети анимация и автосохранение не блокируют текст; видно реальное состояние данных.
37. Система без внешнего интернет-доступа выполняет создание, редактирование, поиск, OCR, DOCX/MD импорт/экспорт в корпоративном контуре.
38. Перенести знания из 1 000 страниц с вложениями; проверить количество объектов, связи и ACL контрольными запросами.
39. Логи аудита показывают ключевые операции; рядовой пользователь не может читать журнал чужого пространства.
40. Статусы всех действий понятны: пусто, загрузка, ошибка, успех, нет доступа, конфликт, восстановлено; никакие клики «в никуда» не допускаются.

## 19. Метрики качества и критерии допуска к релизу
- P0-дефекты (потеря данных, обход прав, повреждение документов, XSS, неработающие копирование/экспорт, расхождение коллаборации) = 0.
- Критические пользовательские потоки из §18 проходят E2E на релизной сборке, в том числе все поддерживаемые браузеры; ни один сценарий не закрывается заглушкой или недействующей кнопкой.
- Точность конвертации оценивать **по семантическим элементам**, не по совпадению пикселей: не менее 99% текстовых символов тестового эталонного DOCX/MD, 100% сохранение структурных элементов базового набора (заголовки, списки, ссылки, простые таблицы), нет бесшумной потери.
- OCR на согласованном RU/EN тестовом наборе: целевая character accuracy ≥ 95% для чётких скриншотов; отдельная матрица по плохим изображениям без ложного обещания 100% распознавания.
- Копирование: 100% автоматизированных типовых сценариев и проверенных ручных сценариев по матрице браузер×приложение назначения.
- SLO из §15 подтверждены нагрузочным тестом; резервное восстановление и отзыв прав — отдельные обязательные протоколы.

## 24. ОБЯЗАТЕЛЬНОЕ ДОПОЛНЕНИЕ: импорт, вставка, таблицы и живой UX уровня Notion (P0)

### 24.1. Продуктовый принцип
- Система должна ощущаться мгновенной, непрерывной и предсказуемой: редактирование происходит прямо на странице, без отдельной кнопки «Сохранить»; пользователь всегда видит состояние синхронизации.
- Функциональный ориентир — Notion, но запрещено копировать фирменные материалы, защищённые элементы оформления и код. Оценивать сценарии, а не пиксельное сходство.
- Одинаковые действия (вставить, перетащить, загрузить, открыть, отменить, восстановить) должны работать единообразно в странице, таблице и вложенном блоке.

### 24.2. Единый конвейер импорта
- Поддержать DOCX, MD/Markdown, CSV, XLSX и вставку через буфер обмена (`text/html`, `text/plain`, `text/markdown`, изображения, файловые объекты). Несколько файлов — пакетно; ZIP с MD и относительными изображениями — с сохранением связей.
- Точки входа: кнопка «Импорт», `/import`, перетаскивание на страницу/раздел, вставка Ctrl/Cmd+V, меню таблицы «Импортировать данные», контекстное меню «Вставить как…».
- Предпросмотр до подтверждения: целевая страница/таблица, количество страниц/строк/изображений, распознанные типы столбцов, предупреждения о неподдерживаемых элементах; режимы «создать новую», «вставить сюда», «добавить в существующую таблицу».
- Импорт выполняется как идемпотентная задача с идентификатором, прогрессом, журналом ошибок и возможностью отмены до фиксации; частичный успех явно обозначается, не маскируется под завершение.
- Оригинальный файл сохраняется по политике организации для повторной конвертации и аудита; проверять MIME, размер, вирусы, zip-bomb, небезопасные URL, HTML и макросы. Импорт не исполняет встроенный код.

### 24.3. DOCX: семантическое преобразование
- Распознавать Word Heading 1–6, обычные абзацы, жирный/курсив/подчёркивание/зачёркивание, ссылки, списки и уровни нумерации, цитаты, таблицы, вложенные изображения, подписи, разделители и сноски (при поддержке схемой).
- Word-стили заголовков должны становиться настоящими заголовками с оглавлением и якорями, а не просто крупным шрифтом.
- Картинки извлекать из пакета DOCX, загружать как отдельные assets, сохранять порядок, подпись, alt-текст и привязку к блоку; исключить битые внешние ссылки.
- Для объединённых ячеек, плавающих объектов, SmartArt, комментариев и track changes показывать точный отчёт о преобразовании. Не терять текст молча; при невозможности преобразования прикладывать исходный файл.

### 24.4. Markdown и вставка текста
- CommonMark/GFM: заголовки, списки, вложенность, ссылки, таблицы, fenced code с языком, изображения, цитаты, чекбоксы, горизонтальные линии; YAML front matter по согласованной схеме.
- Поддерживать относительные пути изображений из ZIP и безопасные удалённые изображения с загрузкой копии в хранилище (с проверкой URL/SSRF).
- При вставке из Word, Google Docs, браузера, ChatGPT и Markdown-редакторов анализировать доступные MIME-представления, сохранять семантику и очищать опасный HTML. Не вставлять весь документ как один неформатированный абзац.
- Вставка Markdown: режимы «распознать разметку» и «вставить исходный текст». Вставка HTML: сохранять заголовки, списки, ссылки, таблицы и картинки, насколько позволяет схема.
- Изображения из буфера: сразу показывать локальный предпросмотр, затем фоновую загрузку; ошибка загрузки не должна уничтожать блок и должна позволять повторить операцию.
- Поддерживать Ctrl/Cmd+Z для отмены одной операции массовой вставки и сохранение позиции курсора после неё.

### 24.5. CSV и XLSX: две разные таблицы
- Разделить «простую таблицу» внутри текста и «структурированную таблицу-коллекцию», где строка — запись с отдельной страницей, а столбцы имеют типы.
- CSV: автоопределение UTF-8/Windows-1251 с ручным выбором, разделителя (`,` `;` tab), кавычек, заголовков, локали дат/десятичных чисел, пустых значений; предпросмотр 100 строк.
- XLSX: выбор листа и диапазона, первая строка как заголовки, перенос значений и форматов даты/чисел; формулы импортировать как вычисленные значения с предупреждением, без исполнения макросов и внешних ссылок.
- Мастер сопоставления столбцов: текст, число, дата, checkbox, single/multi-select, URL, email, пользователь, файл; несовместимые значения подсвечивать, предоставлять варианты «сохранить как текст» или «исправить».
- Варианты: новая таблица, добавить строки, обновить существующие по выбранному уникальному ключу (с dry-run и подтверждением), заменить диапазон. По умолчанию исключить незаметное дублирование при повторном импорте.
- Копирование диапазона из Excel/Google Sheets через Ctrl/Cmd+V должно создавать корректную сетку строк/столбцов. Табличный буфер — TSV + HTML table; экспорт выделения в CSV.

### 24.6. Таблицы уровня Notion
- Простая таблица: вставка/удаление/перемещение строк и столбцов, изменение ширины, выравнивание, выделение диапазона, копирование, закрепление заголовка по возможности, удобное редактирование с клавиатуры.
- Структурированная таблица: типизированные поля, строки как страницы, фильтры с AND/OR, сортировка по нескольким полям, группировка, скрытие/переупорядочивание/закрепление колонок, resize, массовое редактирование, дублирование, поиск, итоговые значения (sum/count/average/min/max), представления Table/List/Board/Gallery по потребности базы знаний.
- В таблицах обеспечить виртуализацию больших наборов строк, отсутствие потери фокуса при прокрутке, предсказуемую клавиатурную навигацию, сохранение пользовательского вида и одновременные правки.
- Не превращать систему в CRM: коллекции предназначены для реестров регламентов, оборудования, стандартов, документов и корпоративных справочников.

### 24.7. Иконки, обложки, файлы, медиа
- Каждая страница и запись таблицы: назначение иконки emoji/из библиотеки, загрузка своей иконки при разрешении; быстрый поиск, замена, удаление, одинаковое отображение в дереве, хлебных крошках и поиске.
- Обложка: загрузка, кадрирование/позиционирование, удаление; отсутствие обложки не должно оставлять пустую область.
- Вложения: drag-and-drop, Ctrl/Cmd+V, выбор файла, пакетная загрузка, прогресс по каждому, пауза/повтор при сбое, предпросмотр поддерживаемых файлов, скачать, скопировать ссылку, переименовать, удалить по правам.
- Изображения: вставка inline или отдельным блоком, изменение размера, выравнивание, подпись, alt-текст, lightbox, загрузка оригинала; thumbnail не заменяет оригинал. Не терять вложения при переносе страницы.
- Для файлов хранить checksum, версию, автора, дату, размер и ссылочную целостность; ограничивать доступ к скачиванию теми же правами, что и к странице.

### 24.8. Ощущение «живого» приложения
- Оптимистическое обновление UI: символы, блоки, иконки, строки и перемещения появляются сразу локально; серверное подтверждение асинхронно.
- Индикатор статуса: «Сохраняется», «Сохранено», «Нет сети», «Не удалось синхронизировать»; не показывать «Сохранено» до подтверждённой фиксации на сервере.
- WebSocket/Yjs или эквивалент для presence, курсоров соавторов, редактирования блоков и таблиц; reconnect с экспоненциальной задержкой и сверкой пропущенных операций.
- Локальный журнал неподтверждённых операций (IndexedDB или аналог), восстановление после закрытия вкладки/сбоя, синхронизация после восстановления сети; конфликт разрешать на уровне операций, а не заменой целой страницы.
- Непрерывность: фоновое обновление дерева, поиска, комментариев и прав; при изменении доступа немедленно блокировать запрещённые операции.
- Микроанимации 120–220 мс для hover, появления меню, перестановки блоков и раскрытия дерева; не анимировать ввод символов, не задерживать взаимодействия; соблюдать prefers-reduced-motion.
- Ориентиры производительности для приёмки на согласованном стенде: отклик ввода p95 < 50 мс, появление локальной правки < 100 мс, доставка удалённой правки p95 < 500 мс при нормальной сети, восстановление после краткого обрыва < 10 с; измерять инструментально.

### 24.9. Защита от потери данных
- ACK только после durable commit; журнал операций и периодические снимки; контроль целостности документов, assets и ссылок; атомарные изменения структуры.
- Сохранять историю и версии независимо от текущего UI; удаление — через корзину с восстановлением; политика хранения версий и вложений задаётся администратором.
- Бэкапы БД, объектов и метаданных в согласованной точке восстановления; шифрование, offsite-копия, тест восстановления ежемесячно. Целевые RPO <= 5 мин и RTO <= 2 ч — подтвердить нагрузочными и аварийными тестами.
- Запретить ложные уведомления «сохранено»; при нехватке места, отказе сервера или отсутствии прав показать ошибку, оставить локальную копию правок и безопасный экспорт черновика.

### 24.10. Дополнительная приёмка (AT-41–AT-60)
- AT-41: DOCX с H1–H4, вложенными списками, таблицами и изображениями превращается в корректные редактируемые блоки.
- AT-42: DOCX с объединёнными ячейками выдаёт отчёт о поддержанных/изменённых элементах и сохраняет оригинал.
- AT-43: Markdown ZIP с относительными картинками создаёт страницы без битых ссылок.
- AT-44: вставка форматированного текста из Word сохраняет структуру заголовков и списков.
- AT-45: вставка HTML из браузера не исполняет скрипты и не теряет безопасные ссылки.
- AT-46: вставка скриншота сразу показывает превью и надёжно завершает загрузку.
- AT-47: отмена вставки 100 блоков одной командой Undo возвращает исходное состояние.
- AT-48: CSV с `;`, Windows-1251 и десятичной запятой импортируется после корректного выбора параметров.
- AT-49: XLSX с тремя листами позволяет выбрать лист/диапазон и сохраняет числа и даты.
- AT-50: повторный импорт в существующую таблицу предлагает dry-run и не создаёт скрытые дубликаты.
- AT-51: вставка диапазона 20×10 из Excel сохраняет геометрию и значения.
- AT-52: фильтры, сортировка, группы, закрепление колонок и итоговые значения работают на 10 000 строк.
- AT-53: иконка страницы обновляется в заголовке, дереве и поиске без перезагрузки.
- AT-54: пакетная загрузка 20 файлов корректно показывает индивидуальные ошибки и повторные попытки.
- AT-55: перемещение страницы с изображениями не ломает медиа и права доступа.
- AT-56: два редактора одновременно меняют один абзац и соседние строки таблицы без потери данных.
- AT-57: обрыв сети во время ввода показывает «Нет сети», хранит операции локально и восстанавливает их после подключения.
- AT-58: закрытие вкладки до серверного ACK не уничтожает локальный черновик.
- AT-59: отказ хранилища не выдаёт ложное «Сохранено», предлагает безопасное восстановление/экспорт.
- AT-60: тестовое восстановление БД и файлов из резервной копии проходит с проверкой контрольных сумм и ссылок.

Изученные публичные материалы Notion: Writing & editing basics; Create your first page; Collaborate in a workspace; Intro to databases; Import data into Notion; Synced blocks; Use pages offline (официальный Help Center, октябрь 2026). Эталон — наблюдаемое поведение, не копирование исходного кода, фирменной графики или точной пиксельной идентичности. Продукт остаётся специализированной базой знаний без универсального таск-менеджмента.

### 25.2. Создание статьи: UX-контракт
- Кнопка «Новая статья» доступна в дереве, в шапке пространства и через Ctrl/Cmd+N; открытие редактируемого документа без модального мастера.
- Фокус сразу в поле названия; после Enter — первый блок; пустая статья содержит ненавязчивые действия «Написать», «Импортировать», «Шаблон», «Таблица».
- Название, иконка, обложка, статус и местоположение можно менять без перезагрузки. Иконка: emoji, библиотека SVG, загруженная иконка; fallback и права на пользовательские изображения.
- Шаблоны статей: регламент, инструкция, FAQ, техническое решение, паспорт продукта, onboarding; администратор задаёт обязательные метаданные и шаблоны пространства.
- В каждом состоянии доступна клавиатурная навигация, видимый фокус, корректный undo/redo и отсутствие потери выделения при открытии меню.

### 25.3. Редактирование: подробная механика
- Блоки: абзац, H1–H3, маркированный/нумерованный/чек-лист, цитата, callout, toggle, код, таблица, изображение, файл, видео/ссылка, разделитель, оглавление, дочерняя страница, синхронизируемый блок.
- Слэш-меню открывается при «/», фильтруется по названию и синонимам RU/EN, управляется стрелками/Enter/Esc; популярные команды первыми; не мешает вводить обычные пути и URL.
- Слева у блока hover-плюс и drag-handle, доступные также по клавиатуре. Перетаскивание с направляющей вставки, вложением, прокруткой у краёв; undo восстанавливает исходное положение.
- Контекстная панель выделения: жирный, курсив, подчёркивание, зачёркивание, inline code, ссылка, цвет текста и фон, комментарий. Положение панели не перекрывает курсор и не уходит за экран.
- Многоабзацное выделение, частичное выделение внутри блоков, copy/cut/paste между страницами, преобразование типа блока с сохранением текста; аккуратное поведение Enter/Backspace/Tab.
- Вложенные колонки и responsive-перестройка; ширина статьи «обычная/широкая», шрифт и размер — настройки представления без порчи семантических данных.
- Копирование выдаёт text/plain и text/html, специальная команда — Markdown; внутренний формат переносит ID/типы блоков безопасно без утечки прав доступа. Вставка приоритетно распознаёт внутренний формат, затем HTML, затем plain text.
- IME-композиция, кириллица, emoji, длинные URL, автозамены и вставка 50+ страниц текста не должны ломать курсор и историю действий.

### 25.4. Импорт как транзакционный конвейер
Шаги: upload -> quarantine/antivirus -> type detection -> parse -> normalize -> media extraction -> schema validation -> preview/diff -> commit -> indexing. Импорт всегда в staging-область: до commit ни одна существующая статья не изменяется. Повторный запуск с тем же import-id идемпотентен.
- DOCX: стили заголовков, списки и вложенность, таблицы, изображения с якорями, гиперссылки, сноски где возможно; таблица несовместимостей и отчёт о преобразованиях.
- MD: CommonMark/GFM, frontmatter, относительные изображения, fenced code, чек-листы, таблицы; пакетный ZIP с контролем traversal и лимитов распаковки.
- Paste: HTML Word/Google Docs/браузер, текст с Markdown-разметкой, изображения clipboard; выбор «с форматированием / только текст / как Markdown», если есть неоднозначность.
- CSV/XLSX: выбор листа, заголовков, разделителя, кодировки, типов полей, предпросмотр 100 строк, сопоставление колонок, диагностика дат/чисел/формул, выбор «простая таблица» либо «коллекция». Формулы не выполняются как код; сохраняется вычисленное значение, если доступно.
- Вложения: drag-and-drop в конкретное место, paste изображения, загрузка с прогрессом, отменой, повтором, проверкой хэша и доступностью после восстановления; alt-text и превью.
- Отдельно: отчёт по каждому импортируемому файлу (готово/предупреждение/ошибка), исходный файл остаётся доступным автору, откат импортированной пачки.

### 25.5. Две модели таблиц
**Таблица документа** — быстрые строки/столбцы, заголовки, выравнивание, ширина, объединение ячеек, копирование диапазонов и вставка из Excel. **Коллекция знаний** — записи с постоянным ID, типизированные свойства (текст, число, дата, выбор, статус, человек, ссылка, файл, checkbox, relation), виды table/list/gallery, фильтр, сортировка, группировка, сохранённые виды. Каждая запись открывается как статья. Не смешивать семантику таблицы документа с БД.
- Виртуализация больших коллекций, sticky headers, доступная навигация стрелками/Tab, массовое редактирование, undo и экспорт CSV/XLSX.
- Никакого неожиданного преобразования простых таблиц в коллекции без подтверждения.

### 25.6. Реальное время и офлайн: протокол сохранения
- Editor state локально; операции CRDT (Yjs) применяются без ожидания сервера. Presence (курсоры, аватары, выделения) передаётся отдельно от долговременного документа.
- WebSocket: reconnect с exponential backoff и jitter, heartbeat, backpressure, повторная отправка неподтверждённых операций. Каждая операция имеет уникальный идентификатор; повторная доставка не создаёт дубликатов.
- Локальный журнал в IndexedDB записывается до показа статуса «сохранено локально»; серверный статус «сохранено» только после durable commit. Очередь синхронизации сохраняется при перезагрузке вкладки.
- Snapshot + append-only update log, периодическая компактификация после подтверждённого snapshot, сохранение истории, отдельная защита от повреждённых/несовместимых CRDT-обновлений.
- Два редактора одного блока, одновременные перемещения, удаление/редактирование, смена прав, истечение сессии, потеря соединения, спящий ноутбук и повторное открытие — отдельные тест-кейсы.
- Для офлайн-доступа — явно выбранные страницы/пространства; видимый индикатор несинхронизированных правок и контроль квоты устройства; операции управления правами недоступны без сервера.

### 25.7. Производительность: измеримые SLO для приёмки
Условия измерений: эталонный ноутбук 8 GB RAM, современный Chromium, сеть RTT 80 ms, 20 Mbps; отдельно low-end mobile. Замеры p50/p95/p99 на холодном и тёплом старте, 10/100 одновременных редакторов, статьи 1/10/100 тыс. слов и коллекции 1/10/100 тыс. строк.
- Ввод: p95 задержки визуального отображения символа <= 50 мс, p99 <= 100 мс для обычной статьи 10 тыс. слов.
- Переход между уже кэшированными статьями: p95 <= 300 мс до отображения содержимого; первая загрузка: p95 <= 2 с до читаемого содержимого при согласованном стенде.
- Синхронизация правок между двумя онлайн-клиентами: p95 <= 500 мс при RTT 80 мс; долговременное подтверждение: p95 <= 2 с в штатном режиме.
- Скролл и перетаскивание: целевые 60 FPS на эталонном стенде; INP p75 <= 200 мс; без long tasks > 200 мс во время обычного набора.
- Импорт, OCR, превью и индексация выполняются вне UI-потока; progress и cancel обязательны. Если SLO нарушен — фиксируется дефект, а не маскируется skeleton-анимацией.

### 25.8. Визуальная система и анимации
- Design tokens: типографика, 4/8 px сетка, радиусы, отступы, цвета, бордеры, тени, состояния hover/focus/active/disabled/error, уровни z-index.
- Контент: ограниченная читаемая ширина, стабильные вертикальные ритмы заголовков/абзацев, адаптивные изображения, код с горизонтальным скроллом, таблицы с аккуратным overflow; отсутствие горизонтального скролла всей страницы на мобильном.
- Макеты: 320/375/768/1024/1440/1920 px, zoom 200%, длинные русские слова, RTL не обязателен, но не должен ломать layout. Тёмная и светлая темы; WCAG 2.2 AA для основных сценариев.
- Анимации 120–220 мс для появления меню/подсказок, 160–260 мс для раскрытия дерева/панелей; easing без чрезмерного bounce. Переходы не должны менять положение курсора, прыгать при загрузке или вызывать layout shift.
- prefers-reduced-motion отключает необязательное движение; анимации transform/opacity по возможности, без тяжёлых blur/box-shadow в длинных списках. Нельзя анимировать каждый символ при вводе.
- Для каждого экрана обязательны состояния loading/empty/error/offline/conflict/permission-denied и проверка визуальной консистентности.

### 25.9. Модель управления и надёжность
- Роли: Reader/Author/Editor/Space owner/Admin/Auditor; ACL наследуются от пространства к странице, возможны явные исключения. Проверка прав на API, поиске, вложениях, websocket-подписках и экспорте; UI не считается защитой.
- Версии статьи: draft, review, published, archived; опубликованная версия может быть стабильной, пока черновик редактируется. Согласование опционально для пространства.
- Администратор управляет пользователями, пространствами, политиками хранения, квотами, журналом действий, задачами импорта и резервными копиями.
- Цели доступности и восстановления для проектирования: 99.9% monthly availability, RPO <= 5 мин, RTO <= 60 мин; подтверждаются нагрузочными испытаниями и фактическим restore drill, а не заявлением в интерфейсе.
- Снимки БД, WAL/PITR, versioned object storage, шифрование, периодическая проверка восстановления, контроль целостности ссылок на файлы и защита от удаления последней доступной копии.

### 25.10. Инженерный процесс: отсутствие регрессий
- Contract tests схемы документа и миграций; property-based тесты undo/redo, paste, CRDT merge; fuzz-тесты HTML/DOCX/Markdown/ZIP; security tests XSS/CSRF/SSRF/path traversal/ACL.
- Playwright E2E в Chromium/Firefox/WebKit, на desktop/mobile; сценарии реального буфера обмена и drag-and-drop, а не только вызов внутренних API.
- Visual regression на всех контрольных ширинах и темах: скриншоты, пороги различий, ручная проверка типографики, переполнений, выделения и курсоров.
- Fault injection: отключение сети на 1/30/300 секунд, перезапуск WebSocket и БД, двойная вкладка, конфликт удаления и редактирования, заполнение локального хранилища, исчерпание диска сервера.
- Метрики продакшена: client errors, input latency, WebSocket reconnect, unsynced queue age, failed import rate, OCR latency, backup age, restore verification, data integrity alerts. Release gates и canary rollout; миграции с rollback-планом.

# Дополнение v1.3 — бесшовный пользовательский опыт и инженерное качество

## 1. Принцип продукта: нулевая пользовательская сложность

Пользовательская цель: «открыл → создал/вставил → поправил → связал → закрыл». Никаких обязательных настроек, режимов редактирования, выбора синтаксиса, ручного сохранения или технических терминов. Продвинутые возможности раскрываются по запросу. Интерфейс документа прежде всего показывает сам документ. Показатель успеха: новый сотрудник без инструкции создаёт и публикует структурированную статью за 3 минуты при наличии готового текста.

## 2. Информационная архитектура и навигация

Левая панель: поиск, избранное, недавние, пространства и дерево страниц, кнопка «Новая страница». У каждой страницы понятное место в дереве, хлебные крошки, постоянная ссылка, понятные действия «Переместить», «Дублировать», «В архив». Быстрый переход Ctrl/Cmd+K, поиск по заголовкам и содержимому, обратные ссылки и блок «Упоминается в». Перемещение не ломает ссылки: ссылки используют постоянные ID, а не путь. Состояние дерева и последняя открытая статья восстанавливаются после перезапуска. Пустые состояния объясняют одно следующее действие.

## 3. Создание статьи без трения

Клик «+ Новая страница» немедленно создаёт черновик и ставит курсор в заголовок; никакого модального мастера. Можно сразу вставить большой текст, DOCX, MD, скриншот или таблицу. Иконка и обложка опциональны, доступны одним кликом. Предлагаются шаблоны «Регламент», «Инструкция», «Паспорт продукта», «FAQ», «Протокол», но пользователь может начать с чистой страницы. Заголовок можно менять без изменения URL/ID. Публикация не обязательна для сохранения черновика; статус виден ясно.

## 4. Интеллектуальная вставка и импорт без потерь

Вставка HTML/RTF/plain-text из Word, Google Docs, браузера и почты: сохранить иерархию H1–H6, абзацы, списки, вложенные списки, таблицы, ссылки, изображения, подписи, цитаты и код там, где это представимо. Не навязывать диалог при обычной вставке. Для неоднозначных данных показать ненавязчивое действие «Вставить как текст / как таблицу / отменить». DOCX и MD: drag-and-drop, кнопка импорта, вставка содержимого; пакетный импорт с предпросмотром дерева и отчётом несовместимостей. Изображения из буфера загружаются как файлы, с устойчивыми ссылками и alt-текстом; ошибка загрузки не удаляет блок. Сложные структуры не уплощать молча. Для CSV/XLSX: выбор листа, диапазона, первой строки заголовков, предпросмотр типов колонок и явное подтверждение, после чего создаётся обычная таблица либо коллекция с фильтрами. Формулы XLSX и макросы не исполнять; сообщать об их судьбе. Сохранять исходник и лог импорта для диагностики.

## 5. Редактор: каждое действие естественно

Enter создаёт абзац; Backspace на пустом блоке корректно объединяет/преобразует; Tab/Shift+Tab работают предсказуемо; Markdown-шорткаты, /-меню, @-ссылки, [[-ссылки, перетаскивание блоков и контекстное меню доступны без конфликтов. Выделение сохраняется при появлении панели форматирования; команды применяются ровно к выделению. Undo/Redo охватывают ввод, вставку, перенос блоков и форматирование, не откатывая чужие изменения. Пустые строки, списки, таблицы и вложенные блоки переживают перезагрузку. При длинных документах сохраняются положение прокрутки, фокус и позиция курсора. Доступна навигация только клавиатурой.

## 6. Визуальный стандарт статьи

Один основной столбец чтения с комфортной шириной строки, опциональная широкая таблица. Система типографических токенов: 6 уровней заголовков, текст, подписи, код, цитаты; согласованные отступы по вертикальному ритму. Таблицы не обрезают текст молча; длинные URL переносятся; изображения имеют предсказуемое масштабирование, подписи, просмотр и выравнивание. Светлая/тёмная тема без скачков размеров. Адаптивность от мобильного экрана до 4K; фиксированные панели не закрывают текст. Содержимое должно выглядеть как законченная статья в режиме чтения и редактирования. Скриншотные эталоны для всех ключевых состояний.

## 7. Анимации и обратная связь

Анимации обязательны, но функциональны: раскрытие дерева, появление меню, drag-preview, создание блока, загрузка файла, переключение панели и подтверждение действий. Обычная длительность 120–220 мс, easing без резких скачков; ввод текста, прокрутка и сохранение никогда не ждут окончания анимации. Уважать prefers-reduced-motion. Не анимировать весь документ при каждом изменении. Skeleton-плейсхолдеры без мигания, спокойные сообщения об ошибках, отсутствие внезапных смещений layout.

## 8. Живое совместное редактирование и офлайн

Ввод отображается локально немедленно; операции пишутся в локальный устойчивый журнал до отправки; сервер подтверждает сохранение, а интерфейс показывает «Локально», «Синхронизация», «Сохранено», «Требуется действие». Presence-аватары и курсоры коллег ненавязчивы. Переподключение с backoff и повторной отправкой идемпотентных операций; нельзя создавать дубликаты. Офлайн-правки не теряются при закрытии вкладки; при переполнении локального хранилища показывается явное предупреждение. Параллельные изменения тестируются на одинаковом блоке, таблице, вложении и при перемещении страницы. Удаление и права доступа имеют предсказуемые правила конфликтов. Серверная долговременная фиксация отделена от локального optimistic UI.

## 9. Производительность и инженерные бюджеты

Измерять p50/p95/p99 на реальных устройствах и документах: 1, 100, 1000 блоков; 20 таблиц; 100 изображений; несколько одновременных редакторов. Ввод до появления символа p95 ≤50 мс; открытие кэшированной статьи p95 ≤300 мс; подтверждённая межклиентская синхронизация p95 ≤500 мс в тестовой сети; отсутствие long tasks >100 мс при обычном наборе. Большие таблицы виртуализировать с сохранением клавиатурного поведения и копирования. Тяжёлые конвертации/OCR выполнять в фоновых заданиях; рендер и сеть не блокируют редактор. Производительность проверять на ограниченном CPU и нестабильной сети, не только на машине разработчика.

## 10. Надёжность, безопасность и восстановление

Операции версионируются и проверяются на целостность; серверный журнал + снимки; резервные копии базы и объектного хранилища с регулярной проверкой восстановления. Ни одна операция импорта не публикует частично повреждённую страницу: сначала staging, валидация, затем атомарная публикация. Удалённые файлы не удалять физически до окончания retention. Проверять права на чтение/изменение/экспорт и вложения на сервере, а не только в UI. Мониторить ошибки синхронизации, очереди импорта, время подтверждения, конфликты, потерянные вложения и восстановление. Формально определить RPO/RTO с владельцем системы до запуска.

## 12. Гейт релиза и критерии простоты

Запрещён выпуск при любом воспроизводимом случае потери текста/вложений, ошибке прав доступа, некорректном восстановлении, зависании редактора при стандартной нагрузке или сломанной базовой вставке. Провести юзабилити-тест минимум на 8 сотрудниках без предварительного обучения: создание, импорт, оформление, перекрёстная ссылка, поиск, экспорт. Замерять время, ошибки, просьбы о помощи, субъективную простоту; перерабатывать проблемные сценарии до повторного теста. Принцип: усложнение модели допускается только при сохранении простого пути по умолчанию. Красота оценивается по утверждённым эталонным макетам и автоматической визуальной регрессии, а не субъективной фразе «похоже на Notion».

# Дополнение v1.4. Дерево страниц, права и эстетика редактора

## 1. UX-контракт боковой панели
- Панель состоит из зон «Поиск», «Избранное», «Пространства», «Общие», «Личные», «Корзина»; каждая секция сворачивается независимо. Содержимое не должно визуально накладываться на соседние элементы при ширине окна от 320 px.
- Строка узла: независимые области стрелки раскрытия, иконки, названия и контекстных действий. Стрелка только раскрывает, название только открывает страницу. Высота строки 36 px, минимальная интерактивная область 32×32 px (для мобильных 44×44 px).
- Базовая ширина 280 px, ручная настройка 240–420 px. Длинные имена обрезаются с многоточием; tooltip, клавиатурный фокус и доступное полное название обязательны. При глубокой вложенности — фокус на ветке и breadcrumbs; запрещено уменьшать полезную ширину названия до нуля.
- Иконка, стрелка, текст и кнопки выравниваются по постоянной сетке; hover-кнопки не перекрывают текст. Стабильные размеры исключают скачки строк при появлении элементов управления.
- Раскрытие/сворачивание 120–180 мс, с учётом prefers-reduced-motion; не анимировать высоту тысячи элементов одновременно. Раскрытое состояние сохраняется отдельно для каждого пользователя; при переходе к странице раскрываются её предки.
- Drag-and-drop показывает три разные цели: перед узлом, после узла, внутрь узла. Доступны клавиатурные аналоги перемещения, Undo, автопрокрутка и предупреждение об изменении прав при переносе.
- Lazy-load дочерних узлов, виртуализация больших списков с корректной доступностью, отсутствие мигания и перестановки строк. Поиск по дереву не раскрывает запрещённые страницы.
- Контекстное меню: новая подстраница, переименовать, изменить иконку, переместить, дублировать, копировать ссылку, в избранное, права, архив/корзина. Опасные операции подтверждаются; обычные — обратимы через Undo.

## 2. Модель разрешений и простое окно «Поделиться»
- Основные режимы: «Только я», «Конкретные пользователи и группы», «Вся компания». Публичная ссылка выключена по умолчанию и разрешается только политикой администратора.
- Уровни: просмотр, комментарии, редактирование, полный контроль; отдельные разрешения на управление структурой, экспорт и предоставление доступа там, где это необходимо.
- Наследование разрешений от пространства и родителей, с явно видимыми исключениями. Окно показывает «Почему у этого человека есть доступ» и итоговый эффективный уровень. Запреты политики безопасности нельзя обойти разрешением дочерней страницы.
- При переносе между разделами предварительно показать, кто приобретёт и потеряет доступ. Для приватной страницы исключить индексацию в чужом поиске, превью, упоминаниях, истории и URL вложений.
- Отзыв доступа применяется сервером немедленно для новых запросов и синхронизаций, с аннулированием временных URL; локально закэшированные копии требуют документированной политики и управляемого срока жизни.
- Операции приглашения/отзыва логируются; права проверяются на сервере для каждой операции и для доступа к файлам, а не только скрытием кнопок в UI. Тестировать сочетания родительских/дочерних прав и групп.

## 3. Палитра и декоративные блоки
- Поддержать H1/H2/H3, жирный, курсив, подчёркивание, зачёркивание, inline-code, гиперссылки, ссылки на страницы, верхний/нижний индекс при необходимости, цитаты, разделители, списки, чекбоксы, таблицы, колонки, оглавление, сноски и раскрывающиеся блоки.
- Цвет текста и подсветки: единая семантическая палитра с нейтральными, красными, оранжевыми, жёлтыми, зелёными, синими и фиолетовыми оттенками. Каждому оттенку задать токены для светлой и тёмной тем; проверять контраст WCAG AA. «Сбросить оформление» — в один клик.
- Callout: иконка/emoji, цвет фона, вложенные абзацы, заголовки, списки, ссылки, изображения; пресеты «Информация», «Совет», «Важно», «Предупреждение», «Ошибка», «Пример» без навязывания пользователю типов.
- Toggle: произвольное вложенное содержимое, раскрытие с клавиатуры, предсказуемое копирование и экспорт. Колонки: drag-and-drop с видимыми границами, на узких экранах последовательная вертикальная компоновка.
- Панель форматирования появляется у выделения и не закрывает выделенный текст, не перехватывает фокус; slash-меню фильтруется по запросу и поддерживает стрелки, Enter, Esc. На touch-устройствах — контекстная панель без hover-зависимости.
- Предустановленные стили страницы: шрифт, ширина контента, плотность, обложка и иконка. Дизайн-токены регулируют интервалы, радиусы, цвета, размеры и анимации централизованно. Никаких произвольных inline-стилей из импортируемого HTML.
- Отображение в режиме чтения должно совпадать с редактором по типографике и расположению; печать, PDF, DOCX и Markdown получают явную матрицу соответствия и отчёт об ограничениях.

## 4. Архитектурные контракты
- Дерево страниц: стабильные UUID, parent_id, sort_key, workspace_id; транзакционная операция перемещения, защита от циклов, версия дерева для конкурентных переносов, курсорная подгрузка. Не делать массовую перенумерацию при каждом перемещении.

# Дополнение v1.5 — корпоративная иерархия, доступы и визуальная система

## Корпоративная иерархия и сущности

Система поддерживает Организацию → подразделения (включая вложенные отделы) → сотрудников; независимо от структуры создаются рабочие группы и пространства знаний. Сотрудник может состоять в нескольких группах, но имеет основной отдел и руководителя. Пространство не обязано совпадать с отделом. Каждая сущность имеет стабильный UUID, имя, описание, владельца, статус, аудит изменений. Удаление отдела не удаляет пользователей или статьи; сначала требуется переназначение прав и владельцев.

## Роли, статусы и матрица полномочий

Тип учётной записи: гость, сотрудник, руководитель. Отдельно: администратор организации, администратор участников, владелец пространства и владелец документа. Руководитель управляет членством в делегированных отделах, но не получает автоматически доступ ко всем секретным документам. Гость видит только явно разрешённые страницы и их разрешённые дочерние страницы. Уровни контента: нет доступа, просмотр, комментарии, редактирование, управление страницей, управление пространством. Возможности экспорта, скачивания, приглашений и публикации задаются отдельными флагами политики; запрет копирования в браузере не является гарантией защиты от утечки.

## Пространства и наследование

Типы пространств: общедоступное внутри организации, закрытое (видно название, вступление по приглашению), приватное (не видно посторонним), личное. По умолчанию новая страница наследует разрешения родителя; исключение отображается явным маркером. При конфликте политик действует запрет верхнего уровня для гостей/внешнего доступа и минимально достаточный доступ. Прямое разрешение не может обойти организационный запрет. Отдельная защищённая дочерняя страница не становится доступной из-за прав на родителя. Перенос между пространствами запускает предпросмотр изменений доступа и подтверждение, если аудитория расширяется.

## Временные и персональные разрешения

Разрешение может назначаться пользователю, группе, отделу или пространству с датой и временем окончания, часовым поясом, автором выдачи и основанием. Быстрые сроки: 1 день, 7 дней, 30 дней, выбрать дату, бессрочно. Истечение выполняется сервером независимо от активности клиента; WebSocket-сеансы и ссылки на вложения немедленно перепроверяют доступ. Администратор видит список истекающих разрешений и может отзывать их досрочно. При удалении сотрудника из отдела доступ через отдел прекращается, но отдельное персональное разрешение отображается как самостоятельный источник доступа.

## UX управления доступами — три шага

Кнопка «Поделиться» открывает компактную панель: 1) поиск человека/отдела/группы; 2) выбор уровня (просмотр, комментарий, изменение, управление); 3) необязательный срок и подтверждение. Видно «Кто имеет доступ» и «Почему»: лично, через отдел, группу, пространство, родителя. Режимы «Только я», «Приглашённые», «Отдел», «Вся компания» представлены понятными пресетами, но интерфейс предупреждает о последствиях переключения. Вкладка «Дополнительно» скрывает редкие политики. По умолчанию внешние публичные ссылки выключены. Запрос доступа должен позволять выбрать причину и отправить запрос владельцу.

## Онбординг, кадровые изменения и offboarding

При создании сотрудника администратор задаёт имя, email, тип, отдел, руководителя и группы; система показывает предварительный список доступных пространств. При переводе в другой отдел предварительно сравниваются потерянные и приобретённые доступы. При увольнении одним действием отключаются сессии, токены, приглашения, временные права, назначаются новые владельцы документов. Неактивные сотрудники остаются в аудите без доступа. Предусмотреть импорт сотрудников CSV, в перспективе SCIM/SSO.

## Техническая модель авторизации

Серверная авторизация на каждом API-запросе, WebSocket-подписке, скачивании вложения, поисковой выдаче, экспорте, предпросмотре и OCR. Модель: RBAC для системных ролей + ACL/группы/наследование для объектов + ограничения политик. Проверка effective_permission(subject, resource, action, time) с трассировкой источников решения. Кэш разрешений с версионированием и инвалидированием при изменении членства/ACL; запрещено доверять клиентскому скрытию элементов. Подписанные URL вложений краткоживущие, отзыв прав должен прекращать выдачу новых URL. Индексы поиска фильтруются по разрешениям на стороне сервера. Все изменения ACL аудируются.

## Визуальный стиль и дизайн-система

Закрепить светлую нейтральную тему как эталон: тёплый белый фон, очень светлые серые поверхности, графитовый текст, мягкие линии разделения, аккуратные тени, скругления 8–12 px. Основной шрифт — Inter либо сопоставимый читаемый sans-serif с качественной кириллицей; системный fallback. Размер основного текста 15–16 px, межстрочный интервал 1.55–1.7; заголовки по типографической шкале. Цветовые акценты: спокойный синий для ссылок, зелёный для успеха, янтарный для предупреждений, красный для ошибок, сиреневый для заметок. Палитра должна работать в тёмной теме и проходить WCAG AA. Запретить произвольные несогласованные цвета для callout: использовать семантические токены и предпросмотр. Поддержать эмодзи/иконки страниц, обложки, цвет текста, фон текста, цвет блока, цитаты, toggle, колонки и подсказки. Сохранять стили при копировании и экспорте, когда формат это позволяет.

## Плавность и анимации

Анимации открытия меню, раскрытия дерева, drag-and-drop и появления панелей 120–220 мс; при prefers-reduced-motion отключать необязательное движение. Анимация не блокирует фокус, набор текста или переключение страниц. При закрытии панели не должно происходить скачков ширины текста; использовать стабильную сетку и корректные переходы. Отдельные скелетоны при загрузке, без бесконечных спиннеров. Виртуализировать длинные деревья и большие списки. Для типичных операций целевые показатели: отклик клика p95 <100 мс локально, раскрытие кэшированной ветки p95 <150 мс, отсутствие заметного layout shift.

## Сценарии проверки и критерии приёмки

A01 Новый сотрудник отдела видит только свои и общие пространства. A02 Гость не видит название приватного пространства в поиске, API и боковой панели. A03 Руководитель не видит личную страницу подчинённого без отдельного разрешения. A04 Права отдела автоматически применяются к новому сотруднику. A05 Исключение доступа к дочерней странице не раскрывает её содержимое через поиск или превью. A06 Перенос приватной статьи в общий раздел требует явного подтверждения. A07 Временный доступ истекает без перезагрузки браузера. A08 Отзыв доступа блокирует активный WebSocket и повторное скачивание. A09 В окне «Поделиться» показаны все источники доступа. A10 Пользователь с доступом только на просмотр не может изменить содержимое через API. A11 Длинные названия отделов и участников не перекрывают элементы. A12 На мобильном доступы управляются без горизонтального скролла. A13 При удалении группы права пересчитываются без осиротевших ссылок. A14 Вложения недоступны по устаревшей ссылке после отзыва доступа. A15 Экспорт соблюдает отдельную политику скачивания. A16 Перевод сотрудника между отделами показывает дифф прав. A17 Деактивация сотрудника отзывает сессии и токены. A18 Цветные callout корректны в светлой/тёмной темах. A19 Анимации отключаются в reduced-motion. A20 Проверка 1000 пользователей, 100 отделов, 500 групп и 100000 страниц с профилированием ACL и поиска. Приёмка: 100% критических сценариев, отсутствие утечек при негативных тестах, визуальные снимки для основных экранов и регрессионные E2E-тесты.

# Дополнение v1.6 — поиск, публикация и администрирование

Дополнение v1.6: поиск, публикация, жизненный цикл статьи, история версий, экспорт, свойства и администрирование. Дополняет требования v1.5, не отменяя их. Сведения о Notion сверены по официальной справке (поиск, публикация, версии, группы, права).

## Поиск: единый UX и четыре области

- Глобальный поиск Ctrl/Cmd+K; поиск по пространству; поиск по текущей странице Ctrl/Cmd+F; поиск по таблице и её свойствам. Область поиска всегда явно показана и меняется одним действием.
- Индексировать заголовки, основной текст, свойства, таблицы, вложенные DOCX/PDF, OCR изображений; показывать путь, фрагмент, подсветку, дату и тип совпадения. Учитывать морфологию русского языка, опечатки, транслитерацию, точные фразы и синонимы.
- Поиск обязан фильтровать результаты по действующим ACL на сервере до ранжирования, подсчёта и выдачи подсказок; закрытые заголовки, фрагменты и названия файлов не должны утекать через автодополнение, кеш и API.
- При изменении доступа индекс и кеш инвалидируются; при переименовании/переносе обновляется путь; при удалении или отзыве доступа результаты исчезают. Для индексации предусмотреть очередь с повторами и мониторинг задержки.
- UX: быстрые результаты при вводе, клавиатурная навигация, недавние статьи, избранное, пустые состояния с подсказкой, переход точно к найденному абзацу; состояние фильтров сохраняется в рамках поиска.
- Цели приёмки на согласованном стенде: p95 подсказки ≤300 мс, p95 полные результаты ≤800 мс при 100 тыс. страниц; изменения прав отражаются в выдаче ≤5 секунд, а прямой доступ блокируется немедленно.

## Публикация и жизненный цикл статьи

- Статусы: Черновик, На согласовании, Опубликовано, Архив. Публикация — отдельная неизменяемая ревизия; читатели видят опубликованную ревизию, редакторы могут готовить новую.
- Публикация внутри компании, в пространстве, конкретным отделам/людям; внешняя публикация только при разрешении политики безопасности. Перед публикацией показывать аудиторию, вложения, дочерние страницы, индексирование и возможность копирования.
- Публичная ссылка: отзыв, срок действия, пароль при поддержке, запрет индексации по умолчанию, контроль скачивания в пределах технических возможностей; явно предупреждать, что уже скачанное нельзя отозвать.
- Копировать постоянную ссылку на статью, заголовок или блок; после переноса ссылки остаются работоспособными через стабильные идентификаторы; переход без прав — безопасная ошибка.
- Печать с отдельными стилями A4, оглавлением, переносами таблиц, скрытием навигации, читаемыми callout и вложениями; предпросмотр перед печатью.
- Экспорт DOCX, MD, PDF, HTML: отдельная статья или дерево, включая изображения/вложения по выбранной политике; отчёт о несовместимых элементах, прогресс, отмена, проверка целостности.
- Дублирование: страница или ветка, выбор места и включения дочерних страниц/вложений; новый ID, понятные правила для внутренних и внешних ссылок, запрет копирования секретных вложений без прав.

## История версий и восстановление

- Журнал изменений и периодические снимки: автор, время, блоки, свойства, таблицы, права и события публикации; история не заменяет резервные копии.
- Просмотр и сравнение двух версий с подсветкой изменений; восстановление всей статьи или выбранного блока. Восстановление создаёт новую версию и сохраняет прежнюю историю.
- Одновременная работа: восстановление требует согласования текущих изменений, предупреждает активных редакторов и не теряет неподтверждённые операции.
- Раздельно управлять версиями черновика и опубликованными ревизиями; предусмотреть хранение, юридическое удержание и политики удаления.

## Свойства страницы и действия

- Единая аккуратная панель свойств: владелец, ответственный, автор, статус, категория, теги, дата пересмотра, версия документа, отдел, конфиденциальность; обязательные поля зависят от шаблона.
- Свойства редактируются прямо в контексте, без перехода в сложные настройки; скрытие необязательных полей, понятные значения по умолчанию и шаблоны.
- Меню действий сгруппировано: Поделиться, Копировать ссылку, Печать, Экспорт, Дублировать, История, Свойства, Переместить, Архивировать, Удалить. Видимость и доступность соответствуют разрешениям.

## Администрирование, роли и визуальная прозрачность

- Единый административный центр: обзор, люди, отделы, группы, пространства, роли, гости, временные приглашения, публикации, аудит. Поиск, фильтры, массовые операции, подтверждение критических действий.
- Матрица эффективного доступа «пользователь × пространство/страница»: показать уровень, источник права, срок, владельца и конфликтующие правила; предпросмотр «что видит пользователь» без нарушения конфиденциальности.
- Мастер добавления сотрудника: приглашение, роль организации, отдел(ы), группы, доступные пространства, срок при необходимости, итоговый предпросмотр. Отзыв и перевод между отделами немедленно пересчитывают права.
- Принцип наименьших привилегий: администратор пользователей не автоматически читает приватный контент; отдельные полномочия для управления публикацией, политиками, аудитом и контентом.
- Панель контроля: внешние ссылки, истекающие приглашения, открытые пространства, сиротские страницы, владельцы, подозрительные массовые экспорты; все действия журналируются.

# ДОПОЛНЕНИЕ V1.7 — ПРОСТОТА, ПОЛНОТА, ОТКАЗОУСТОЙЧИВОСТЬ И ПЕРЕНОСИМОСТЬ

## A. Продуктовая философия и приоритеты
**Приоритеты по порядку:** (1) отсутствие потери данных и нарушений доступа; (2) предсказуемое редактирование; (3) скорость; (4) простота и визуальное качество; (5) широта возможностей. Функции не добавлять на главный экран только потому, что они реализованы. Основной пользовательский путь: открыть → написать/вставить → получить правильную структуру → автоматически сохранить → закрыть. Никакого обязательного выбора типа страницы, формата хранения или режима редактора. Сложные настройки — в контекстном меню, доступном по необходимости.

### A1. Измеримые UX-контракты
- Новая статья: одна команда «Создать», сразу фокус в названии; текст можно вставить немедленно. Создание дочерней статьи — кнопка `+` у родителя и понятная команда из статьи.
- Вставка из DOCX/браузера/Markdown: предварительно интерпретировать заголовки, списки, таблицы, изображения, ссылки; показывать ненавязчивый результат и кнопку «Отменить». Не запускать модальное окно, если операция однозначна.
- Контекстное меню выделения, `/`-команды, `@`-ссылки, drag-and-drop, понятные tooltips, единые горячие клавиши, сохранение позиции курсора после асинхронных операций.
- Открытие страницы, смена ветки и сворачивание дерева не должны сбрасывать несохранённые правки или положение прокрутки без предупреждения.
- Пустые состояния объясняют следующий шаг, ошибки содержат понятное действие восстановления. Не допускать декоративных неработающих кнопок.
- Цели испытаний: не менее 90% новых сотрудников без обучения создают и оформляют статью; не менее 95% находят существующую; 0 критических потерь данных в аварийных сценариях. Измерять время и ошибки, а не только субъективную оценку.

## B. Целостность базы знаний и жизненный цикл
- Владелец, ответственная группа, дата последней проверки, срок следующей проверки, статус «проверено»/«требует пересмотра»; напоминания и фильтр устаревших знаний. Для обычной заметки эти поля скрыты по умолчанию.
- Шаблоны «Регламент», «Инструкция», «FAQ», «Паспорт продукта», «Решение инцидента»; можно создавать свои. Шаблон задаёт блоки и свойства, но не блокирует свободное редактирование.
- Подтверждённые регламенты можно заблокировать от случайного изменения; обновления проходят через черновик и согласование, опубликованная редакция неизменна до следующей публикации.
- Синхронизируемые блоки: одна каноническая версия и встраивания с проверкой прав; при отсутствии доступа показывать заглушку, не раскрывать текст.
- Обратные ссылки, проверка битых ссылок, автоматическое обновление пути при перемещении, неизменные идентификаторы страниц.
- Корзина с восстановлением ветки и её прав; отдельные правила хранения и юридической блокировки удаления, если включены политикой организации.

## C. Архитектура надёжности
- PostgreSQL как источник истины для метаданных, ACL, журналов и опубликованных ревизий; CRDT-обновления фиксировать в долговечном журнале, периодически создавать согласованные снимки. Redis — только кэш/временное состояние, не единственное место хранения изменений.
- Объектное хранилище с версионированием файлов, контрольными суммами SHA-256, проверкой целостности и защитой от случайного удаления. Все вложения, обложки и изображения включены в резервирование.
- Идемпотентные операции создания/переноса/импорта, транзакции для изменения дерева и прав, outbox для поисковой индексации и уведомлений, повторная обработка без дублей.
- Клиент: локальный журнал неподтверждённых операций, честный статус «локально», «на сервере», «ошибка»; восстановление после закрытия вкладки, обрыва сети и повторного входа. Никогда не показывать «Сохранено» до долговременного подтверждения.
- Кластеризация приложений и WebSocket-шлюзов, health checks, rolling deploy, graceful shutdown, rate limiting, защита от перегрузки импорта и OCR; фоновые задания в очереди.
- Наблюдаемость: метрики задержек редактора, отказов синхронизации, ошибок импорта, состояния индекса, очередей, резервных копий, свободного места; алерты с владельцем реакции.

### C1. Резервные копии и восстановление — обязательный договор
- Определить и согласовать целевые SLO: доступность 99,9% в месяц; RPO не более 5 минут для подтверждённых сервером изменений; RTO не более 2 часов для полной организации. Это **проектные цели**, не гарантии без испытаний и инфраструктурного бюджета.
- Непрерывное архивирование WAL и point-in-time recovery PostgreSQL; ежедневные полные резервные копии и дополнительные инкрементальные/дифференциальные согласно выбранному ПО; согласованные снимки файлов и метаданных.
- Минимум 3 копии в 2 независимых средах хранения, 1 из них вне основного контура; шифрование, отдельные ключи и ограниченные права, неизменяемое/защищённое хранение от ransomware.
- Политика хранения: ежедневно 30 дней, еженедельно 12 недель, ежемесячно 12 месяцев — настраиваемые стартовые значения, уточняемые юристами и ИБ.
- Ежедневная автоматическая проверка выполнения и контрольных сумм; ежемесячное тестовое восстановление отдельных страниц и вложений; ежеквартальное восстановление всей организации в изолированной среде с протоколом времени и сверкой количества страниц, ACL, ссылок и файлов.
- Процедуры: восстановить страницу, пространство, организацию на выбранную точку времени; сначала предпросмотр влияния, затем восстановление как новая версия/новый контур, без безвозвратного затирания актуальных данных.
- Защитить резервные копии от администратора приложения с компрометированным аккаунтом: отдельные роли и учётные данные backup-оператора.

## D. Полный архив, экспорт и импорт обратно
- **Два разных режима:** (1) пользовательский экспорт DOCX/MD/PDF/HTML/CSV/XLSX в пределах разрешений; (2) административный переносимый архив всей организации, включая приватные страницы, только через отдельную высокопривилегированную, подтверждаемую и аудируемую операцию.
- Архив содержит манифест со схемой и версией формата, идентификаторы организации/пространств/страниц, дерево, свойства, опубликованные версии, историю (согласно политике), комментарии, права и группы, вложения, медиа, связи, хеши, журнал ошибок экспорта. Секреты, пароли и токены не экспортировать.
- Выгрузка в ZIP/набор томов для больших объёмов, с прогрессом, возобновлением и проверкой целостности. Шифрование архива, ограниченная по времени ссылка, обязательный аудит скачивания.
- Обратный импорт архива: dry-run и отчёт о совместимости, конфликтах ID и отсутствующих файлах; выбор «новая организация» либо «восстановление в изолированный контур»; транзакционное переключение после валидации.
- Критерий полноты: после экспорта и импорта число страниц, структура дерева, внутренние ссылки, ACL, версии, изображения и вложения совпадают по манифесту; отсутствующие элементы перечислены явно. Восстановление нельзя считать успешным только по факту открытия ZIP.
- Экспорт не должен незаметно обходить права: обычный пользователь видит только разрешённое; архив всей организации — строго отдельная административная процедура с двойным подтверждением.

## E. Администрирование без сложности для рядового сотрудника
- Панель «Здоровье системы»: состояние сервисов, задержки, последнее успешное резервирование, последнее успешное тестовое восстановление, свободное место, неуспешные задания и экспортные архивы.
- Простые вкладки: Сотрудники, Отделы, Группы, Пространства, Доступы, Публикации, Аудит, Резервирование, Импорт/экспорт. Массовые операции с предпросмотром затронутых объектов и отчётом.
- Мастер приглашения: имя/email → роль → отделы → пространства → срок доступа (для гостя) → подтверждение. После назначения показывать эффективные права.
- Доступы по умолчанию минимальные; отзыв сотрудника немедленно блокирует новые запросы, токены и ссылки; незавершённые синхронизации обрабатываются по политике доступа.

## F. Дополнительные обязательные проверки
- F01: пользователь вставляет многостраничный документ с таблицами, изображениями и ссылками; заголовки и медиа остаются корректными, Undo возвращает исходное состояние.

- F03: разорвать соединение во время ввода, закрыть браузер, восстановить сеть: локальные изменения восстанавливаются, статус не вводит в заблуждение.
- F04: имитировать падение приложения, Redis и одного узла WebSocket: содержимое не теряется; повторные операции не создают дубликаты.
- F05: восстановить базу и файлы на точку времени, проверить права, версии, поиск, вложения и обратные ссылки.
- F06: полный экспорт организации → проверка SHA-256 → импорт в чистый контур → автоматическая сверка манифеста и выборочная ручная проверка.
- F07: обычный сотрудник не может экспортировать закрытые страницы или получить их через индекс, CDN, OCR, ссылки и вложения.
- F08: восстановить удалённую ветку, не сломав внутренние ссылки и наследование разрешений.
- F09: проверить макеты 320, 375, 768, 1024, 1440, 1920 px; нет перекрытий, прыжков, горизонтального скролла редактора и потерянных элементов управления.
- F10: провести usability-тест на новых сотрудниках без обучения: создание, оформление, ссылка, поиск, совместная работа, экспорт и восстановление.

# Дополнение v1.8. Человекочитаемый архив, безупречный редактор и отсутствие тупиковых сценариев

## 1. Непреложный принцип архива
Полный экспорт организации — ZIP с открытой, понятной структурой папок и документов. Он пригоден для чтения обычными файловыми менеджерами и редакторами без установки приложения. Каноническая переносимая форма содержимого — Markdown (UTF-8) плюс оригинальные вложения; дополнительно пользователь выбирает экспорт DOCX для чтения и печати. DOCX не является единственным форматом восстановления: он не может надёжно сохранить все связи, ACL, версии и типы блоков. Машиночитаемые манифесты JSON дополняют, но не заменяют читаемые MD-файлы.

Пример состава: README.md; spaces/Проектирование/Регламенты/Инструкция--page-id.md; assets/images/; assets/files/; databases/Таблица.csv; databases/Таблица.schema.json; metadata/pages.json; metadata/permissions.json; metadata/users.json; metadata/groups.json; metadata/versions/; metadata/manifest.json; checksums/SHA256SUMS; export-report.md. Названия папок и файлов читаемые, стабильные идентификаторы предотвращают коллизии. Внутренние ссылки в MD относительные и работают после распаковки; идентификаторы обеспечивают точное восстановление перекрёстных ссылок.

README.md на человеческом языке объясняет структуру, дату экспорта, объём, ограничения, порядок чтения и восстановления. Страницы сохраняют заголовки, списки, таблицы, цитаты, изображения, подписи, callout (с понятным fallback), ссылки, файлы и метаданные. Для сложных блоков рядом хранится переносимое расширение и понятное статическое представление. Никакой контент не теряется молча: export-report.md фиксирует все преобразования.

## 2. Экспорт и обратный импорт организации
В настройках: «Скачать архив организации», «Скачать пространство», «Скачать страницу», «Восстановить из архива». Экспорт включает выбор: контент и вложения; + версии; + права/организационная структура; + журналы (только уполномоченным). Экспорт — фоновая задача с прогрессом, повтором и проверкой контрольных сумм. Секреты, пароли, токены, ключи шифрования никогда не включать. Данные пользователей выгружаются с учётом законных оснований и политики конфиденциальности.

Импорт: проверка ZIP против zip-slip, zip bomb, вредоносных вложений и повреждений; чтение манифеста; dry-run с отчётом; выбор «новая организация / отдельное пространство / объединение»; карта пользователей и отделов; предварительный просмотр конфликтов идентификаторов и названий; подтверждение; транзакционное применение или компенсирующий откат; итоговый отчёт. Ссылки, ACL, история и вложения восстанавливаются, где они присутствуют и допустимы. Отсутствующих пользователей назначать в «неразрешённые идентичности» с закрытым доступом до сопоставления, не раскрывать приватное по умолчанию.

Критерий приёмки: export → распаковка и чтение без приложения → импорт в чистую инсталляцию → автоматическая сверка количества страниц, блоков, файлов, таблиц, версий, ссылок, ACL, контрольных сумм; выборочная визуальная сверка. Обязательные ежеквартальные учения на независимой инфраструктуре. Человекочитаемый архив — средство переносимости, а не замена горячим бэкапам БД и журнала транзакций.

## 3. Изображения: редактор как Notion, но без потерь
Вставка через Ctrl+V, drag-and-drop, файловый диалог, URL с проверкой безопасности; моментально показывать локальное превью и прогресс загрузки. Автоматически сохранять оригинал и производные оптимизированные версии; не заменять оригинал сжатыми данными. EXIF-ориентация, HEIC при поддержке, SVG с безопасной очисткой, прозрачность, анимация GIF, ошибки форматов. Размер изменяется перетягиванием видимых при наведении ручек с сохранением пропорций по умолчанию, поддержкой клавиатуры и Undo. Выравнивание слева/центр/справа, варианты ширины, подпись, alt-текст, замена изображения без потери подписи, открытие полноэкранного просмотра, скачивание оригинала. На узких экранах изображение не выходит за контейнер; адаптивные размеры, отсутствие layout shift благодаря резервированию места по aspect ratio. При перемещении блока не терять фокус, подписи, вложенные ссылки и историю.

## 4. Файлы, иконки, ярлыки и блоки
Вложения — красивые компактные карточки: иконка типа, название, размер, состояние, превью по возможности, скачать, заменить, переименовать, удалить, открыть; никаких обрезанных кнопок или перекрытий. PDF — безопасный просмотр; Office — предпросмотр, если сервис доступен, иначе понятное скачивание. Вложения перемещаются как блоки, могут быть выровнены и сгруппированы в колонки; все действия доступны с клавиатуры. Для страниц: emoji, библиотека пиктограмм, собственная иконка, обложка, смена и удаление; единые размеры, отступы и выравнивание в дереве, поиске и заголовке. Иконки не должны влиять на высоту строк неожиданно.

Блочный редактор: hover-ручка перетаскивания, меню «+», slash-команды, превращение типов блоков, множественное выделение, дублирование, перемещение, Undo/Redo, автосохранение, копирование rich text/MD/plain text, корректная вставка из DOCX/Google Docs/HTML/Excel. Контекстные панели не перекрывают текст; поддержка IME, экранных читалок, мобильного touch и zoom 200%. Цвета и callout выбираются из единой адаптивной палитры с проверкой контраста.

## 5. Полное покрытие сценариев и запрет тупиков
Для каждого действия описать: исходное состояние, happy path, пустые данные, медленную сеть, офлайн, потерю прав во время действия, конфликт изменений, превышение квоты, неверный файл, повторный клик, отмену, Undo, восстановление после перезапуска, мобильный и клавиатурный сценарии. Любое сообщение об ошибке отвечает: что случилось, сохранены ли данные, что сделать дальше, как повторить. Нельзя оставлять пользователя в модальном окне без выхода, с бесконечным spinner, недоступной кнопкой без причины, потерянным выделением или исчезнувшим блоком.

Составить реестр состояний для каждого компонента: idle/hover/focus/loading/empty/success/error/offline/permission denied/conflict. Каждому действию — наблюдаемый результат и тест. Не добавлять настройки, если есть безопасное разумное значение по умолчанию. Тяжёлые операции — в фоне; ввод текста не блокируется OCR, загрузкой или экспортом.

## 7. Правило релиза
Релиз запрещён при любой воспроизводимой потере содержимого, ошибке доступа, повреждении архива, невосстанавливаемой копии, блокировке ввода, критическом перекрытии элементов интерфейса или тупиковом пользовательском сценарии. ## 3. Интерактивная механика и геометрия (P0)
У каждого popover, tooltip, menu, drawer, dialog определены anchor, границы viewport, fallback-сторона, максимальная высота, внутренний скролл, z-index, focus trap при модальности, возвращение фокуса и Escape/outside click. При открытии меню не допускается непредсказуемое смещение контента. Hover не выполняет действия; click/Enter/Space выполняют. Hover-меню не должны мерцать при перемещении указателя между триггером и панелью. Для действий по наведению всегда есть видимый или клавиатурный эквивалент.

Дерево: стрелка меняет expanded, название открывает страницу, меню ⋯ управляет элементом; hit areas не перекрываются. Сохранение expanded/scroll/selection при навигации и возврате; lazy load с индикатором и повтором при ошибке; доступная клавиатурная навигация; drag/drop с индикаторами before/inside/after, проверкой прав и undo. Дочерние страницы доступны как в sidebar, так и в теле родительской статьи; у двух представлений одна и та же модель данных.

# ДОПОЛНЕНИЕ v2.0 — ЭТАЛОН РЕДАКТОРА: ТЕКСТОВАЯ ПАЛИТРА, ВЫДЕЛЕНИЕ, ВСТАВКА, КЛАВИАТУРА И DRAG-AND-DROP

Статус: P0. Применять совместно со всеми ранее определёнными требованиями. Визуальный эталон: лаконичный светлый интерфейс, графитовая типографика, мягкие поверхности, деликатные границы, спокойные цветовые акценты. Все команды доступны мышью и клавиатурой, критические — также на touch.

## 1. Модель редактирования и UX-контракт
- Редактор блочный, но выделение и копирование ощущаются как в привычном текстовом процессоре. Курсор, выделение, IME-композиция, автосохранение, история Undo/Redo и совместное редактирование должны быть согласованы.
- Три способа вызвать команды: плавающая палитра при выделении текста; /-меню при вводе в пустом или текстовом блоке; ⋮⋮-меню блока и кнопка + на левом поле. Команды не дублируются в нескольких постоянно видимых панелях.
- При наведении появляются только неопасные контекстные кнопки. При клике раскрывается меню. Палитра позиционируется относительно выделения с автоматическим переносом вверх/вниз, удерживается в пределах viewport, не закрывает текст и не вызывает скачков.
- Выделение сохраняется при взаимодействии с палитрой, color picker, выпадающим списком шрифтов и диалогом ссылки. Возврат фокуса — в исходное место. Нажатие Esc закрывает верхний слой без потери текста; последовательный Esc возвращает фокус редактору.
- Состояния: normal, hover, focus, selected, mixed-format, loading, disabled, error, success, readonly, offline, conflict, collaboration. Для mixed-format кнопки показывают смешанное состояние, а не ложное значение.

## 2. Панель форматирования
- Основная строка: стиль абзаца (текст/H1/H2/H3/цитата), семейство шрифта, размер, жирный, курсив, подчёркнутый, зачёркнутый, моноширинный inline-code, ссылка, цвет текста, фон текста, дополнительные действия. Часто используемые функции видны сразу, остальные — в меню «Ещё» без горизонтального переполнения.
- Палитра цвета: 10–12 согласованных семантических цветов и 10–12 мягких подложек, «без цвета», последние использованные; предпросмотр при hover без фиксации; применение по клику. Цвет и фон независимы. Контраст текста должен оставаться доступным в светлой и тёмной теме. Пользовательские HEX/RGB — в расширенном режиме, при соблюдении корпоративной политики.
- Шрифты: 3 рекомендованных пресета (современный sans, serif, mono) и расширенный управляемый список корпоративно разрешённых шрифтов с fallback и корректной кириллицей; предпросмотр и поиск по имени. Не допускать десятков хаотичных гарнитур в одном документе: по умолчанию применяется единый стиль страницы, локальные переопределения доступны по необходимости.
- Размер: стили H1/H2/H3 предпочтительнее ручного масштабирования; ручной размер через ограниченную шкалу 12/14/16/18/20/24/28/32 с возможностью сброса. При вставке сохранять семантическую структуру и корректный межстрочный интервал.
- Выравнивание текста: влево, по центру, вправо; по ширине — только если качество переносов и отображение на мобильном подтверждены. Для изображений и файлов — отдельные правила выравнивания. Отступы, межстрочный интервал и ширина страницы должны быть предсказуемыми.
- Ссылки: Ctrl/Cmd+K по выделению; вставка URL поверх выделенного текста предлагает «Сделать ссылкой» без потери текста; изменение адреса/названия/открытия, снятие ссылки; предпросмотр и проверка безопасности URL; внутренние ссылки на страницы и блоки, автодополнение [[ и @. Не создавать дубли при повторной вставке.

## 3. Списки и структурные блоки
- Маркированный, нумерованный, чек-лист, многоуровневые списки, toggle, цитата, callout, код, разделитель, таблица, вложенная страница, колонки.
- Enter создаёт следующий пункт; Enter на пустом пункте завершает список; Tab/Shift+Tab меняют вложенность, если это не конфликтует с доступностью; Backspace в начале объединяет или меняет тип блока по документированному правилу.
- Нумерация пересчитывается корректно при вставке, удалении, переносе и объединении; доступны «начать с N» и «продолжить нумерацию». Чекбокс меняет состояние только по явному клику/Space, не при попытке выделить текст.
- Преобразование блоков не теряет содержимое, вложенность, комментарии, ссылки и идентификаторы там, где преобразование совместимо; несовместимые преобразования предварительно объясняются.

## 4. Выделение, copy/paste и drag-and-drop
- Поддержать выделение слова/строки/фрагмента, диапазона через несколько блоков, блока целиком и нескольких блоков; Shift+стрелки, Ctrl/Cmd+A (контекстно: блок → статья), Esc (текст → блок), двойной/тройной клик; точное восстановление позиции курсора.
- Copy/Cut/Paste между собственными статьями сохраняет стили, вложенность, таблицы, ссылки, изображения и блоки, если есть права; перенос в другое приложение — корректные text/html и text/plain. Вставка из Word/Google Docs/веба/почты — безопасная нормализация HTML с сохранением допустимого форматирования, списков, таблиц и ссылок; очистка вредоносного HTML и трекеров. Ctrl/Cmd+Shift+V — вставить без форматирования.
- Вставка из Excel/CSV распознаёт таблицу, не превращает всё в одну строку; многострочный текст в ячейках и табуляция корректно обрабатываются. Перенос больших файлов/изображений — с индикатором прогресса, отменой, повтором и без блокировки набора текста.
- Drag handle ⋮⋮ у блока появляется в предсказуемом месте; drag начинается после порога перемещения, с явной линией вставки до/после/внутрь. Автопрокрутка возле краёв, вложенность, перенос между колонками, Ctrl/Alt-копирование там, где применимо, клавиатурный аналог, отмена одним Undo. Нельзя потерять блок при сбое сети или отказе прав.
- При копировании/перемещении между пространствами проверяются права, наследование и вложения; до потенциально опасного перемещения показывается ясное предупреждение.

## 5. Горячие клавиши и команды
- Ctrl/Cmd+B — жирный; I — курсив; U — подчёркивание; K — ссылка; Z — отмена; Shift+Z или Ctrl+Y — повтор; C/X/V — копировать/вырезать/вставить; Shift+V — без форматирования; F — поиск по странице (с учётом браузерных конфликтов); Ctrl/Cmd+P — печать; Ctrl/Cmd+Shift+M — комментарий при отсутствии системного конфликта.
- Markdown-автозамены: #/##/### + пробел → H1/H2/H3; -/*/+ + пробел → маркер; 1. + пробел → нумерация; [] → чек-лист; > + пробел → toggle; --- → разделитель; **текст** → жирный; *текст* → курсив; `текст` → inline code.
- /-меню: клавиатурный поиск по командам, синонимы на русском и английском, недавно использованные, стрелки, Enter, Esc. Команды не перехватывают обычный ввод внутри кода, URL, IME или при экранировании.
- Отдельный справочник клавиш с поиском, отображением сочетаний для Windows/macOS, разрешением конфликтов с браузером, раскладками RU/EN и screen readers. Запрещено обещать системные комбинации, которые браузер не позволяет перехватить.

# 21. UX v2.1 — полноэкранные изображения, перенос, помощь, история действий и шаблоны

## 21.1. Полноэкранный просмотр изображений

По нажатию на изображение (если пользователь не находится в режиме изменения размера) открывать lightbox поверх приложения; отдельная команда «На весь экран» использует весь viewport, а при поддержке браузером Fullscreen API — системный полноэкранный режим. Zoom 25–800%, кнопки +/−, 100%, «Вписать», «Оригинал», колесо мыши с модификатором или явно управляемое колесо, двойной щелчок, pinch-to-zoom и pan при увеличении; центрирование по точке курсора/жеста. Esc закрывает просмотр; стрелки переключают изображения статьи; доступно скачивание оригинала согласно ACL. Просмотр не изменяет размеры изображения в документе. Ограничить выход за границы, предотвращать случайную прокрутку страницы под просмотрщиком, учитывать EXIF-ориентацию, загрузку оригинала по требованию, очень большие схемы, медленную сеть и ошибки. Подпись, имя, масштаб и действия читаемы на мобильном.

## 21.2. Перемещение блоков, изображений и статей

Единый drag-and-drop: на hover слева от блока появляются + и ручка ⋮⋮ без сдвига контента; на touch — долгое нажатие на ручку или доступное меню «Переместить». Drag preview с прозрачностью, линия вставки между блоками, подсветка целевой колонки/контейнера, авто-прокрутка у краёв, явные недопустимые цели; отпускание выполняет одну атомарную операцию. Поддержать перемещение нескольких выбранных блоков, между колонками и страницами, в том числе изображений, таблиц, вложенных блоков, сохранение порядка, ссылок и ID. В дереве статей: перенос между родителями, изменение уровня вложенности, раскрытие целевой папки по задержке, прокрутка, клавиатурная альтернатива «Переместить в…» с поиском, предотвращение циклической вложенности, проверка прав, защита от гонок и понятное подтверждение результата. Ошибочный перенос отменяется Ctrl/Cmd+Z или кнопкой «Отменить» в кратком уведомлении.

## 21.3. Подсказки и встроенная помощь

Каждая иконка имеет tooltip с названием и клавишной комбинацией, показываемый с небольшой задержкой на hover и при фокусе клавиатуры. Не перекрывать текст и соседние кнопки; tooltip автоматически меняет сторону у краёв viewport. Для впервые использующих редактор — ненавязчивые одноразовые подсказки на ключевых действиях (выделение, /, +, перетаскивание, колонки, таблицы, файлы), с «Понятно»/«Не показывать». Центр помощи с быстрым поиском по действиям, короткими GIF/видео/схемами и интерактивными примерами; вызывается из «?» и по F1, если сочетание не занято системой. Пустые состояния содержат контекстные инструкции. Не показывать навязчивые туры при каждом входе; сохранять факт прохождения и уважать reduced motion и accessibility.

## 21.4. Undo/redo и журнал действий

Ctrl/Cmd+Z — отмена; Ctrl/Cmd+Shift+Z и Ctrl+Y — повтор, с учётом платформы. История редактирования локальной сессии фиксирует атомарные операции: ввод, форматирование, вставку, удаление, перенос, resize, преобразование блоков, изменение таблиц, изображений и структуры страницы. Группировать непрерывный набор текста, но не склеивать несвязанные действия. Предоставить меню истории рядом с кнопками отмены/повтора: список с временем, типом операции, объектом и автором; безопасный переход к состоянию локальной сессии с предпросмотром и подтверждением, если откат затронет множество операций. Не путать undo/redo с версионной историей документа: последняя хранит серверные снимки/ревизии, diff, автора, время, просмотр и восстановление как новую ревизию. При совместной работе undo отменяет только собственные операции пользователя и не откатывает чужие изменения; конфликты разрешать без потери данных. После перезагрузки граница доступной undo-истории явно обозначена, история документа остаётся доступной. Запретить ложные обещания отката, если операция необратима.

## 21.5. Шаблоны и примеры

Создать библиотеку не менее 30 качественных шаблонов с миниатюрой, кратким назначением, предпросмотром и кнопкой «Использовать»: инструкция/SOP, регламент, база FAQ, онбординг, чек-лист, протокол встречи, решение/ADR, техническое ТЗ, архитектура, паспорт продукта, карточка оборудования, инцидент/postmortem, баг-репорт, тест-кейс, тест-план, релиз-ноты, дорожная карта, план проекта, журнал рисков, база поставщиков, каталог материалов, страница команды, политика безопасности, инструкция по эксплуатации, руководство пользователя, технический обзор, справочник терминов, шаблон таблицы, шаблон колонок, галерея изображений, библиотека файлов, ретроспектива, предложение по улучшению. Каждый шаблон — полностью редактируемые реальные блоки, демонстрирующие списки, таблицы, 2–4 колонки, картинки, вложения, callout, toggle, ссылки и TOC. Создание из шаблона не меняет оригинал. Поддержать избранные и корпоративные шаблоны с версиями и правами.

## 21.6. Качество анимаций и адаптивность

Hover-состояния 100–160 мс; мягкая обратная связь при drag без инерционного промаха; изменения структуры анимировать 120–220 мс, если не мешает скорости. Не анимировать ввод текста, курсор и саму операцию сохранения. При prefers-reduced-motion отключать декоративные движения. Контроль на 320/375/768/1024/1440/1920 px, touch, мыши, клавиатуре, масштабировании 200%, длинных названиях, 4-колоночных макетах и вложенных таблицах; никаких наложений, горизонтального скролла всей страницы из-за одного блока, пропажи фокуса и невидимых управляющих элементов.

# Дополнение v2.2 — нативный просмотр изображений, глубокая история и бесконфликтная совместная работа

## 1. Полноэкранный просмотр изображений (P0)

**UX-контракт:** одно нажатие на изображение открывает полноэкранный lightbox с тёмным нейтральным фоном и режимом «вписать в экран». Изменение масштаба в просмотрщике никогда не меняет размеры блока в документе. Повторное открытие не должно вызывать скачков, задержек или потерю места чтения. Кнопки появляются при движении указателя/касании, исчезают при бездействии; остаются доступны клавиатуре и screen reader.

**Компьютер:** колесо мыши над изображением плавно масштабирует относительно позиции указателя (точка под курсором визуально остаётся на месте); прокрутка вниз уменьшает, вверх увеличивает. Захват левой кнопкой и перемещение панорамируют изображение («рука» как в PDF); курсор `grab`/`grabbing`. Поддержать trackpad pinch, двойной щелчок для удобного масштаба, `+`/`-`, `0` — вписать, `1` — 100%, `Esc` — закрыть, стрелки — переход к соседнему изображению только когда не конфликтуют с панорамированием. Масштаб ориентировочно 10–800% (конкретные пределы и поведение сверхкрупных оригиналов проверяются прототипом). Не перехватывать колесо вне просмотрщика; внутри — исключить случайный скролл страницы.

**Телефон и планшет:** pinch-to-zoom двумя пальцами с масштабом относительно центра жеста, панорамирование одним пальцем увеличенного изображения, двойной тап для увеличения/возврата, инерция с мягким ограничением по границам, без резких рывков и «пружинящих» пустых областей. В масштабе «вписать» свайп переключает изображения, при увеличении свайп панорамирует и не переключает случайно. Учитывать safe-area, ориентацию экрана, системный жест назад, браузерный zoom, touch-action/pointer events, экранную клавиатуру, accessibility и prefers-reduced-motion. При закрытии возвращать фокус, позицию прокрутки и контекст статьи.

**Качество рендера:** использовать исходное изображение с progressive loading/тайлингом для очень больших чертежей; не размывать при увеличении сверх доступного разрешения без предупреждения; EXIF-ориентация, SVG с санитизацией, PNG с прозрачностью, длинные/узкие изображения; защита от OOM. Для тяжёлых схем — индикатор загрузки оригинала, не блокирующий управление. Zoom/pan должны обновляться через transform с requestAnimationFrame и без layout thrashing. Целевые показатели: визуальный отклик на жест <50 мс, движение ~60 fps на типовом поддерживаемом устройстве, отсутствие потери кадров сериями в тестовых сценариях; измерять на реальных устройствах, не обещать универсально 60 fps.

## 2. История: операции, версии, восстановление (P0)

**Три уровня, не путать:** (A) мгновенные undo/redo для локальных осмысленных операций, (B) подробный журнал изменений документа с автором, временем, типом операции и ссылкой на изменённый блок, (C) неизменяемые версии/снимки для долгосрочного восстановления. Операции набора текста группировать логически (пауза/граница слова/смена блока), не создавать сотни пунктов за каждую букву. Структурные действия (перенос блока, изменение таблицы, удаление, вставка, смена прав, перенос страницы) фиксировать отдельно.

**Восстановимость:** каждая подтверждённая сервером операция должна иметь устойчивый идентификатор и позицию в журнале; серверный журнал append-only с идемпотентностью, периодические снимки для ускорения восстановления. Пользователь может открыть историю, выбрать точку времени/операцию, просмотреть предварительную реконструкцию и сравнение, восстановить весь документ либо выбранный блок (когда корректно), не уничтожая более новые изменения. Восстановление — новая операция/версия, которую также можно отменить через последующее восстановление. Для совместных документов глобальный undo не должен без подтверждения откатывать чужие изменения; локальный undo ориентирован на собственные операции и учитывает их преобразование относительно параллельных правок.

**Глубина хранения — проектная политика:** оперативный журнал операций минимум 90 дней, снимки/версии минимум 365 дней, для критичных документов — бессрочно либо по настраиваемой политике организации; юридическое хранение и стоимость согласовать отдельно. Не обещать восстановление каждого отдельного нажатия клавиши: гарантировать восстановление состояния после каждой *подтверждённой смысловой операции*, а для набора — после зафиксированных групп изменений. Показывать границы гарантии и состояние синхронизации. Включить сохранение версий вложений и метаданных, защиту от удаления связанных файлов и проверку ACL при просмотре истории.

**UX:** `Ctrl/Cmd+Z`, `Ctrl/Cmd+Shift+Z` (дополнительно `Ctrl+Y` Windows); компактные кнопки со списком последних операций через стрелку/долгое нажатие; отдельная панель «История» с фильтрами по автору, дате, блоку, типу; визуальный diff и режим «Посмотреть версию» без возможности случайно её отредактировать. В мобильном интерфейсе полноценный просмотр и восстановление. Доступ к истории зависит от прав; запись в аудит обязательна.

## 3. Одновременное редактирование и конфликты (P0)

**Архитектурное требование:** rich-text/block CRDT (например, Yjs/Automerge либо эквивалент с доказанной корректностью) с детерминированным слиянием параллельных операций, уникальными ID блоков, порядком и ссылочной целостностью. Не применять наивную стратегию «последний сохранивший перезаписывает весь документ». Серверная валидация схемы, прав и инвариантов структуры обязательна. При операциях с таблицами, колонками, удалением/перемещением страниц и изменением ACL предусмотреть транзакционную/серверную координацию поверх CRDT, а не полагаться на слияние текста.

**Сценарии:** два человека печатают в разных блоках; одновременно в одном абзаце и одной позиции; один форматирует диапазон, другой удаляет часть текста; один перемещает блок, другой редактирует его; один удаляет таблицу, другой добавляет строку; двое одновременно переносят одну страницу; один теряет сеть и продолжает локально, затем возвращается; права пользователя отзывают во время редактирования; два устройства одного пользователя; конфликт версий вложений; восстановление исторической версии при активной работе других пользователей. Для каждого сценария — предсказуемый результат, сохранение всех допустимых изменений, уведомление при невозможности автоматического объединения, восстановление отвергнутых локальных правок в отдельный черновик/экспорт, без молчаливой потери.

**UX присутствия:** ненавязчивые аватары, цветные курсоры/выделения и имя по hover; не закрывать текст, скрывать лишнее при плотном присутствии. Статусы «Сохранено», «Синхронизация», «Офлайн — изменения на устройстве», «Требуется внимание» должны соответствовать реальному состоянию подтверждения. После переподключения — синхронизация с сохранением позиции курсора, selection и прокрутки. Если операция не может быть корректно слита, показать понятный диалог сравнения и варианты: сохранить обе версии, принять серверную, сохранить локальную копию; не скрывать конфликт.

**Надёжность:** журнал операций с ack, retry/backoff, идемпотентность, sequence/vector clocks по выбранной модели, периодическая проверка согласованности, контроль orphan-блоков и циклов иерархии, безопасная миграция схемы документа. Тесты property-based/fuzz, сетевые partition/latency/reorder/duplicate, 2–20 активных редакторов, нагрузка и восстановление из snapshot+log; обязательный инвариант — после доставки всех допустимых операций клиенты сходятся к одинаковому документу без потери подтверждённых данных.

# Дополнение v2.3 — личные пространства, дерево страниц, непрерывная работа и синхронизация

## 1. Принцип продукта
Интерфейс минималистичен и предсказуем: документ занимает главное место, инструменты контекстны, частые операции выполняются без модальных цепочек. Сложность контроля доступа, версий, синхронизации и восстановления скрыта под капотом. Публикация — осознанное действие, не побочный эффект автосохранения.

## 2. Личное пространство каждого сотрудника
- Автоматически создаётся при первом входе: «Моё пространство»; по умолчанию доступно только владельцу и не отображается в корпоративном поиске для других пользователей.
- Разрешены любые типы страниц и блоков, вложенные страницы, таблицы, вложения, шаблоны, черновики и экспериментальные структуры; автосохранение и история работают как в командных пространствах.
- Личные страницы не публикуются и не становятся доступными по ссылке автоматически. Публикация или перенос в командное пространство требует явного действия и проверки эффективных прав.
- Перенос в общую область: диалог с целевым пространством и родителем, предварительным просмотром будущего пути, аудитории, унаследованных разрешений и вложений; подтверждение; после операции — ссылка на новое местоположение и «Отменить» в пределах допустимого окна.
- «Поделиться» личной страницей — отдельная осознанная операция с указанием адресатов, уровней доступа и срока; явная индикация, что страница больше не полностью личная. Запрещены неявные публичные ссылки.
- Увольнение/блокировка: политика передачи или архивирования рабочих материалов из личной области с аудитом, без автоматического раскрытия частных заметок. Администраторские аварийные процедуры — по документированной политике, с ограниченными полномочиями и журналированием.
- Квоты и вложения показываются ненавязчиво; при превышении лимита содержимое не удаляется, доступны безопасные действия.

## 3. Левое дерево, вложенные статьи и навигация
- Группы: «Моё пространство», «Командные пространства», «Избранное», «Недавние»; сохраняемые раскрытия, выбранная страница, ширина панели, прокрутка и история назад/вперёд.
- Hover строки: справа появляется маленький «+» (создать дочернюю страницу) и «⋯» (действия); без изменения ширины строки и без скачков. На сенсорных экранах действия доступны через явную кнопку меню.
- Нажатие «+» немедленно создаёт черновик под выбранным родителем, фокусирует название; Escape при пустом черновике корректно отменяет создание, без мусорных страниц. Enter подтверждает название; создание устойчиво к повторному нажатию и плохой сети.
- Клик по стрелке раскрывает дерево, клик по названию открывает статью; клавиатура: стрелки, Enter, Space, контекстное меню, доступные подсказки.
- Перетаскивание страницы: видимый ghost, линия вставки и подсветка будущего родителя; автопрокрутка, авторазворачивание узла после небольшой задержки, ясная индикация запретных целей. Исключены циклы (страница внутрь самой себя или потомка), перемещения без прав, потеря ссылок и дублирование узлов.
- При переносе между пространствами — предварительная проверка прав и наследования, вложений, внутренних ссылок; атомарная серверная операция, аудит, уведомление при конфликте.
- Тысячи страниц: ленивое получение дочерних узлов, виртуализация длинных списков, стабильная прокрутка и мгновенное локальное раскрытие уже загруженных ветвей.
- Создание дочерней страницы также доступно из тела родительской статьи, через slash-меню и контекстное меню, с одинаковой семантикой.

## 4. Онлайн-синхронизация и непрерывная работа
- WebSocket (или эквивалентный двунаправленный транспорт) используется для присутствия, курсоров, изменений, уведомлений и обновления дерева. HTTPS API — для начальной загрузки, файлов, поиска и критических команд; конкретный транспорт выбирается по нагрузочным испытаниям.
- Локальная очередь неподтверждённых операций с устойчивыми идентификаторами и повторной отправкой без дублей (идемпотентность). Подтверждение сервера отделено от локального отображения: состояния «Изменения на устройстве», «Синхронизация», «Сохранено», «Требуется действие».
- Переподключение с экспоненциальной задержкой и случайным разбросом; догоняющая синхронизация от подтверждённой ревизии, сверка контрольных версий, восстановление пропущенных событий. При недоступности WebSocket — резервный механизм получения обновлений без ложного статуса «Сохранено».
- Совместное редактирование — CRDT/OT-подход с проверкой конкретной реализации. Структурные операции (перемещение страниц, права, публикация, удаление, вложения) валидируются сервером транзакционно, даже если текст объединяется автоматически.
- При конфликте, который нельзя безопасно объединить, сохраняются обе версии и предоставляется понятное сравнение, без молчаливого перезаписывания. При восстановлении соединения — никаких внезапных скачков курсора и прокрутки.
- Восстановление после перезагрузки вкладки, сна устройства, переключения сети и работы двух вкладок; локальный черновик не теряется до серверного подтверждения. Ограничения офлайн-режима ясно обозначены.
- Вложенные файлы: отдельные возобновляемые загрузки с проверкой целостности; блок не выдаёт файл за доступный до подтверждения успешной загрузки.

## 5. Производительность, подгрузка и пагинация
- Не показывать пользователю техническую пагинацию там, где естественнее непрерывная прокрутка и постепенная подгрузка: дерево, поиск, недавние, списки шаблонов.
- Серверная курсорная пагинация для длинных выборок и журналов; виртуализация отображения, предзагрузка соседнего окна, сохранение позиции после возврата. Для аудита и истории — явная возможность перейти к дате/фильтру.
- Длинные документы загружаются без блокировки набора текста; тяжёлые медиа — лениво, с резервированием размеров, без скачков вёрстки. При больших таблицах — виртуализация только если не ломает выделение, навигацию, копирование и доступность.
- Проектные целевые показатели, проверяемые на согласованном оборудовании и сети: отклик локального ввода без заметной задержки, визуальный отклик типичных действий в пределах ~100 мс, раскрытие загруженной ветки без сетевого ожидания; численные SLA уточняются после профилирования и нагрузочного стенда.
- Измерять INP, время первого взаимодействия, задержку синхронизации p95/p99, пропущенные кадры drag-and-drop, размер локальной очереди, время восстановления соединения; бюджеты регрессии в CI.

## 6. Контекстная помощь и пустые состояния
- Первое посещение личной области: короткий ненавязчивый пример и действие «Создать первую страницу»; без обязательного обучающего тура.
- Подсказки к «+», «⋮», ручке переноса, правам, публикации и статусу синхронизации; клавиатурные сочетания в tooltip; встроенный поиск по справке.
- Пустое дерево, пустая статья, отсутствие прав, нет сети и ошибка загрузки имеют ясное сообщение и безопасный следующий шаг; никаких пустых зависших экранов.

# 2.4. Обязательная промышленная готовность, устранение неопределённостей и надёжная синхронизация

## 2.4.1. Безусловный критерий результата: эксплуатационная готовность «под ключ»
Поставляемый результат — законченная, развёрнутая, документированная, протестированная и пригодная для повседневной эксплуатации корпоративная база знаний. Прототип, демонстрация, частично работающее MVP, неоформленные заглушки, необработанные ошибки и «сделаем позже» не считаются выполнением ТЗ. Внешне система остаётся лаконичной, понятной без обучения, быстрой и ненавязчивой; сложность реализуется внутри платформы.

До сдачи должны быть завершены не только функциональные сценарии, но и развёртывание, миграции, мониторинг, резервирование, восстановление, управление доступом, обновления, техническая и пользовательская документация, обучающие примеры, инструкции администратору и операционные регламенты. Никакие функции не должны вести в тупик, показывать нерабочие кнопки или незавершённые состояния.

## 2.4.2. Принятие решений без «белых пятен»
При неоднозначности исполнитель самостоятельно формирует варианты, оценивает влияние на UX, безопасность, сохранность данных, производительность, мобильность и сопровождение; выбирает решение по приоритету: (1) отсутствие потери данных и нарушение прав, (2) корректность и предсказуемость, (3) простота ежедневной работы, (4) скорость и доступность, (5) визуальная лаконичность и плавность, (6) стоимость сопровождения. Решение оформляется в журнале архитектурных решений (ADR) с предпосылками, альтернативами, обоснованием, последствиями и проверкой. Существенные изменения требований согласуются с заказчиком; самостоятельное закрытие пробелов не даёт права менять утверждённый объём работ или бизнес-правила без согласования.

До финальной приёмки ведётся реестр открытых вопросов и дефектов с владельцем, решением и подтверждением тестом. Не допускаются нерешённые критические и высокоприоритетные дефекты; средние и низкие должны быть либо исправлены, либо отдельно письменно приняты заказчиком без риска потери данных, безопасности и ключевых сценариев. Визуальные дефекты переполнения, наложений, некорректных hover-меню, drag-and-drop, адаптивности и потери фокуса считаются дефектами продукта, а не косметикой.

## 2.4.3. Технологически нейтральная надёжная онлайн-синхронизация
WebSocket не является обязательным единственным способом связи. Архитектура выбирается по доказуемым свойствам: низкая задержка доставки, устойчивость к разрывам, корректное объединение параллельных изменений, безопасное восстановление и наблюдаемость. Допустимы WebSocket, HTTP streaming/SSE, периодическая синхронизация как резервный канал и иные обоснованные механизмы. Для конкурентного редактирования требуется модель согласования операций (например, CRDT или эквивалентная доказанная модель), а не last-write-wins для всего документа.

Клиент локально фиксирует ещё не подтверждённые операции; сервер выдаёт устойчивое подтверждение после надёжной записи. Интерфейс честно различает «изменения локально», «синхронизация», «сохранено на сервере», «нет соединения» и «требуется вмешательство». При переподключении применяется повторяемая синхронизация с идентификаторами операций, идемпотентностью, упорядочением/каузальностью, контролем пропусков, повторной передачей и дедупликацией. Права доступа перепроверяются сервером при записи, восстановлении и скачивании. Изменения при отзыве прав не публикуются автоматически, а безопасно сохраняются для разрешённого экспорта/разбора согласно политике доступа.

Параллельные правки разных абзацев и совместимые правки одного абзаца объединяются без потери символов; перемещения/удаления одних и тех же блоков, изменение структуры таблиц, вложенных колонок и метаданных обрабатываются детерминированно. Если безопасное автоматическое слияние невозможно, система сохраняет обе версии и предлагает понятное разрешение конфликта без молчаливой перезаписи. Курсоры и присутствие коллег — вспомогательные эфемерные данные и не должны влиять на сохранность содержимого.

## 2.4.4. Измеримые критерии надёжности и быстродействия
Пороговые значения ниже — целевые требования для проектирования и приёмки; измеряются в согласованной эталонной среде и под типовой нагрузкой, а не заявляются без испытаний.
- Доступность продуктивного сервиса: целевой SLO не ниже 99,9% в месяц, исключения и порядок учёта оговорены в SLA.
- Локальный отклик набора и основных действий редактора: p95 не более 100 мс на поддерживаемых устройствах в типовом документе; тяжёлые операции сопровождаются честной индикацией.
- Отображение удалённого подтверждённого изменения у другого активного участника: p95 не более 500 мс при нормальной сети, без обещания такого результата при офлайне.
- Ни одна подтверждённая сервером операция не теряется при перезагрузке, повторном входе, переподключении или отказе одного экземпляра приложения.
- Восстановление после аварии: проектные RPO ≤5 минут и RTO ≤2 часов, с регулярным подтверждением испытаниями и отдельным учётом неподтверждённых локальных изменений.
- История: журнал смысловых операций не менее 90 дней и версионные снимки не менее 365 дней либо более длительный срок согласно политике организации; гарантии восстановления документированы и проверены.
- Поддерживаемые размеры документов, объём вложений, число одновременных редакторов и нагрузочные профили должны быть определены до испытаний, измерены и зафиксированы в паспорте эксплуатации.

## 2.4.5. Полная матрица приёмки: не только happy path
Для каждого сценария проверяются обычный, граничный, ошибочный, конкурентный и восстановительный пути. Обязательные группы: редактор/форматирование; блоки и drag-and-drop; дерево и права; таблицы и колонки; изображения и полноэкранный просмотр; файлы и скачивание; поиск и подгрузка; мобильные/планшеты/клавиатура; версия/undo/redo; публикация и личные пространства; импорт/экспорт; администрирование; онлайн/офлайн; безопасность; обновления; резервное восстановление.

Отдельные сквозные испытания: (A) два пользователя одновременно меняют одну строку и разные блоки; (B) один перемещает блок, другой его редактирует; (C) одновременно меняют структуру таблицы; (D) сеть обрывается в момент записи, клиент перезапускается и повторно подключается; (E) вкладки расходятся по версии; (F) права отзываются во время редактирования; (G) сервер перезапускается во время активной сессии; (H) загрузка файла прерывается; (I) восстанавливается версия и тут же выполняется undo/redo; (J) проводится реальное восстановление из резервной копии в отдельной среде; (K) проверяются 320–1920 px, 200% zoom, iOS/Android, сенсорный ввод и сниженная анимация; (L) тестируются тысячи страниц и большие таблицы без нарушений вёрстки.

Проверки автоматизируются на уровне unit, component, integration, API, E2E, property-based и нагрузочных/chaos-тестов по уместности. Для совместного редактирования применяются рандомизированные конкурентные последовательности операций с проверкой сходимости, отсутствия потерь, повторов и повреждения дерева документа. Все обнаруженные дефекты сопровождаются воспроизводимым сценарием и регрессионным тестом.

## 2.4.6. Эксплуатация, сопровождение и финальный gate
Поставка включает: воспроизводимый deployment (включая конфигурацию и секреты без включения их в репозиторий), миграции и откат релиза, health/readiness checks, метрики/логи/трейсы, оповещения, резервные копии и тесты восстановления, аудит, эксплуатационный runbook, инструкции администратора, пользовательскую справку, шаблоны и обучающие примеры, перечень поддерживаемых браузеров/устройств, схему данных, описание протокола синхронизации, паспорт ограничений и отчёт испытаний.

До запуска обязательны: тестовая эксплуатация с реальными ролями и документами, нагрузочное испытание, проверка доступности, анализ угроз и проверка прав, тест восстановления после сбоя, ручная UX-проверка всех ключевых сценариев и адаптивности, контроль регрессий, пилотное внедрение, план переключения и возврата. Итоговая приёмка проводится по чек-листу с доказательствами (протоколы, скриншоты, журналы тестов и результаты восстановления). Формулировка «готово» допустима только после прохождения gate, а не после написания кода.

OPS-012: корректное отображение долгих операций. OPS-013: мониторинг и тревоги. OPS-014: полный аудит изменений. OPS-015: мобильная и планшетная регрессия. OPS-016: доступность с клавиатуры. # Версия 2.5. Администрирование пользователей, областей видимости и прав доступа

## 1. Принцип и модель доступа
Система обязана предоставлять единый лаконичный интерфейс управления доступом, не требующий знания ACL/RBAC. Роль пользователя в организации, его членство в подразделениях/группах, область видимости материала и конкретные разрешения — независимые сущности. Интерфейс показывает эффективные права с объяснением их происхождения. Доступ по умолчанию закрыт (deny by default); отсутствие разрешения означает запрет. Все проверки производятся сервером, включая API, поиск, вложения, экспорт, предпросмотр, историю и WebSocket-события.

Субъекты: владелец организации, администратор, руководитель подразделения (делегированные полномочия), сотрудник, гость, группа, подразделение, вся организация. Административная роль сама по себе не должна автоматически открывать содержимое личных пространств; экстренный доступ возможен только по явно утверждённой политике, с причиной и аудитом.

Объекты: организация, подразделение, группа, пространство, папка/страница, дочерняя страница, вложение, версия, шаблон. Области видимости: «Только я», «Приглашённые», «Группа», «Подразделение», «Вся компания», «Гости по приглашению». Публикация в общую область — явное действие с предпросмотром аудитории. Личное пространство по умолчанию приватно.

Разрешения: просмотр, комментирование, редактирование, управление структурой (создание/перемещение/удаление дочерних страниц), управление доступом, администрирование пространства. Скачивание и экспорт могут ограничиваться отдельными политиками, но интерфейс обязан ясно показывать такие ограничения. Не смешивать возможность редактировать статью с правом выдавать доступ третьим лицам.

## 2. Удобное назначение и отзыв
Диалог «Поделиться / Доступ» показывает: текущую область видимости; список людей, групп и подразделений; уровень прав каждого; срок действия; статус (активен, ожидает, приостановлен, истёк); источник права («напрямую», «через отдел», «через группу», «унаследовано от пространства»). Быстрые действия: пригласить гостя, добавить сотрудника, выбрать подразделение, выбрать всю компанию, установить роль, срок начала и окончания, приостановить, возобновить, отозвать. Поиск с автодополнением, группировка, фильтры, массовое назначение с предпросмотром последствий. Опасные действия подтверждаются без лишних диалогов, с возможностью отмены там, где безопасно.

Временный доступ: дата/время начала и конца с часовым поясом, автоматическое истечение на сервере, немедленное прекращение выдачи содержимого, отмена активных ссылок и подписок; напоминание владельцу перед истечением — опционально. Приостановка пользователя блокирует все его активные сессии/токены и доступ к материалам без удаления профиля, истории авторства и аудита. Возобновление не восстанавливает уже истёкшие временные приглашения автоматически.

Гость имеет доступ только к явно разрешённым объектам и их необходимым родительским навигационным оболочкам, без доступа к каталогу сотрудников, глобальному поиску и другим разделам. Гостевые права не распространяются на всю компанию по умолчанию. Приглашения — с ограниченным сроком действия, проверкой адресата и возможностью отзыва.

## 3. Наследование, конфликты и перемещение
Права могут наследоваться сверху вниз. Для дочерней страницы доступны «Наследовать» и «Настроить отдельно» с понятным предупреждением о последствиях. Для исключений нужна формально определённая модель: явные ограничения безопасности и запреты имеют приоритет над разрешениями; далее вычисляются разрешения из прямых назначений и членств. Отсутствие доступа к родительской странице не должно автоматически раскрывать её закрытые метаданные при доступе по прямой ссылке к дочерней. Проверка эффективных прав должна быть одинаковой в UI и API.

При перемещении статьи между подразделениями/пространствами показывать до подтверждения: прежнюю и будущую аудиторию, какие права сохранятся, какие изменятся, какие ссылки/гости будут затронуты. Нельзя незаметно сделать закрытый документ доступным всей компании. При повышении видимости требовать явного подтверждения уполномоченного пользователя. При копировании статьи не копировать чувствительные приглашения автоматически. Отмена перемещения возвращает структуру и права согласованно.

## 4. Административные экраны
Экран «Люди и доступ»: пользователи, гости, подразделения, группы, приглашения, приостановленные и истёкшие доступы. Экран «Кто имеет доступ?» доступен из каждой статьи и показывает эффективную аудиторию и причины. Экран «Проверить доступ» позволяет администратору выбрать пользователя и документ и увидеть: «может/не может», перечень действий и цепочку наследования без имитации чужого входа. Обязательны поиск, фильтры, понятные пустые состояния, пакетные операции с предпросмотром и безопасным подтверждением. Администрирование работает на мобильном и планшете без скрытых hover-only действий.

## 5. Безопасность, синхронизация, аудит
Изменения прав применяются атомарно и проверяются при каждом запросе. После отзыва сервер прекращает новые чтения, скачивания, экспорт, поиск и потоковую доставку данных; существующие WebSocket-подписки пересматриваются или разрываются. Кэш и поисковый индекс учитывают ACL; старые подписанные URL ограничены по времени и отзывны по политике. Уже скачанные на устройство файлы технически нельзя гарантированно отозвать — интерфейс и политика безопасности не должны обещать обратного.

Аудит: кто, когда, кому, на какой объект, какое право назначил/изменил/отозвал, срок, источник, причина, прежнее и новое значение, результат. Доступ к журналу ограничен; журнал защищён от обычного редактирования. Восстановление старой версии документа не должно откатывать текущие ACL без отдельного административного действия.

## 6. Приёмочные сценарии ACL-151—ACL-174
ACL-151. Новый личный документ виден только владельцу.
ACL-152. Сотрудник подразделения видит только разрешённые разделы и документы.
ACL-153. Документ открыт всей компании на просмотр, но редактируется только авторами.
ACL-154. Сотруднику выдано право редактирования без права делиться документом.
ACL-155. Гость приглашён на одну статью и не видит другие материалы.
ACL-156. Временный доступ автоматически прекращается в заданный момент.
ACL-157. Приостановленный пользователь теряет доступ с действующих сессий.
ACL-158. Возобновление не продлевает истёкшее приглашение.
ACL-159. Права подразделения наследуются дочерними страницами.
ACL-160. Исключение на дочерней странице корректно отображается и применяется.
ACL-161. Экран объясняет, почему конкретный пользователь имеет право.
ACL-162. Прямой URL к закрытой статье не раскрывает содержание и метаданные.
ACL-163. Поиск и подсказки не показывают закрытые статьи.
ACL-164. Превью, вложения, экспорт и история защищены теми же правами.
ACL-165. Перемещение в открытое пространство предупреждает о расширении аудитории.
ACL-166. Отмена перемещения возвращает структуру и права.
ACL-167. Копирование не переносит гостевые приглашения без согласия.
ACL-168. Отзыв прав прекращает поток обновлений и доступ к вложениям.
ACL-169. Две параллельные операции изменения прав не теряют обновления.
ACL-170. Массовое назначение показывает точную аудиторию до подтверждения.
ACL-171. Гость не может получить корпоративный доступ через навигацию или API.
ACL-172. Изменение прав фиксируется в защищённом аудите.
ACL-173. Восстановление версии статьи не восстанавливает старые разрешения.
ACL-174. Все операции доступны клавиатурой, с экрана 320px и на планшете.

## 7. Критерий завершения
Система управления правами считается готовой только после тестов на сервере, API, UI, поиске, вложениях, потоковых подписках, конкурентных изменениях и мобильных устройствах. Не допускаются скрытые исключения, молчаливое расширение аудитории и рассинхронизация отображаемых и фактических прав. Технические решения, не указанные явно, принимаются по принципам минимальных привилегий, прозрачности, простоты и сохранности данных; решения документируются и тестируются.


# РАЗДЕЛ QA-2.6. ТОТАЛЬНАЯ ПРОВЕРКА ПОЛЬЗОВАТЕЛЬСКИХ ДЕЙСТВИЙ И ПРОМЫШЛЕННАЯ ПРИЁМКА

## 1. Обязательный принцип полной приёмки

Система не считается готовой, пока не проверено каждое доступное пользователю действие, каждый визуальный элемент и каждый переход состояния. «Работает в основном», «поправим потом», «не удалось воспроизвести» без расследования — не критерии сдачи. Цель — промышленная готовность, непрерывная работа и субъективное качество взаимодействия не хуже эталонных сценариев Notion; это проверяется воспроизводимыми сравнительными испытаниями, а не декларацией. Проверки охватывают корректность, скорость, понятность, визуальную целостность, доступность, безопасность и устойчивость к сбоям.

## 2. Матрица полного покрытия интерфейса

Для каждого экрана, элемента, состояния и доступного действия создать запись: ID, компонент, исходное состояние, устройство, способ ввода, предусловия, действие, ожидаемый результат, ожидания по анимации и времени, проверка сохранения, undo/redo, негативный сценарий, автоматизированный тест, ручной тест, фактический результат, дефект, владелец и доказательство. Инвентаризация строится из маршрутов приложения и реестра UI-компонентов; пропущенные действия блокируют релиз. Для интерактивных компонентов проверяются normal/hover/focus/active/disabled/loading/error/empty/overflow; появление и скрытие подсказок, popover, modal, меню и drag-preview; клавиатура, мышь, touch и screen reader по применимости.

## 3. Полный перечень взаимодействий редактора

Проверить ввод, выделение мышью/клавиатурой/пальцем, двойной и тройной клик, Shift-выделение, копирование, вырезание, вставку plain/rich text/HTML/Word/Excel, перетаскивание, форматирование, ссылки, комментарии, slash-меню, контекстную панель, заголовки, списки, чекбоксы, таблицы, объединение ячеек, сортировку/фильтры там, где предусмотрено, вложения, изображения, 1–4 колонки, изменение ширины, вставку и удаление блоков. Каждое действие проверяется в пустом/заполненном документе, при длинных данных, после Undo/Redo, после перезагрузки и при конкурирующих изменениях. В таблицах — выравнивание по горизонтали и вертикали, автоувеличение высоты, перенос длинных слов/ссылок, вставка диапазонов, добавление строк/столбцов, изменение размеров без выхода контента за границы.

## 4. Перемещение и навигация

Проверить drag-and-drop блоков, изображений, таблиц, вложенных страниц и целых ветвей дерева: между соседними блоками, в/из колонок, между статьями, между разделами при наличии прав, на краях экрана с автопрокруткой, в свернутые узлы, при медленном/быстром перемещении и отмене перетаскивания. До отпускания отображать точную точку вставки и изменение уровня вложенности. Недопустимы потеря содержимого, создание циклов иерархии, случайное раскрытие доступа, скачки прокрутки и дублирование объекта. Проверить плюсик у страницы, раскрытие/сворачивание, breadcrumbs, back/forward, поиск, избранное, пагинацию/виртуализацию и сохранение положения.

## 5. Изображения, файлы, полный экран

Проверить просмотрщик изображений: открытие/закрытие, масштабирование колесом относительно курсора, pan с зажатой кнопкой, touch pinch-to-zoom, перемещение одним пальцем увеличенного изображения, двойное касание, reset, ориентацию экрана, изображения с экстремальным соотношением сторон и очень большим разрешением. При закрытии возвращаться в исходную позицию документа. Проверить иконку файла, просмотр, быстрое скачивание, прогресс, ошибки, повтор, длинные имена, права на вложения, мобильное сохранение и работу с недоступным файлом. Ни одно меню не должно выходить за viewport.

## 6. Undo/Redo, версии и восстановление

Проверить каждую редактирующую операцию на обратимость и повтор, последовательности из 1/10/100/1000 действий, объединение ввода в смысловые транзакции, границы истории после перезагрузки, восстановление версии, сравнение и возврат к текущей версии. Восстановление не должно уничтожать последующие версии; журнал аудита не подменяется. Тестировать восстановление документа и отдельных блоков, после удаления/архивации, на фоне совместного редактирования. Отдельно проверить фактическую глубину хранения по политике, очистку и законность доступа к истории.

## 7. Импорт, экспорт, резервное копирование

Обязателен round-trip тест: создать репрезентативную базу с деревом, ссылками, вложениями, таблицами, форматированием, изображениями, колонками, правами и версиями; экспортировать; открыть архив без приложения; импортировать в чистую установку; машинно сравнить дерево, ID/ссылки, контент, файлы (контрольные суммы), разрешения и доступные версии по заявленной модели. Проверить ZIP/Markdown и остальные поддерживаемые форматы, кириллицу, спецсимволы, длинные имена, пустые и большие документы, битый архив, частичный импорт, отмену, повтор без дублей, конфликты имён, безопасную обработку путей и отказ при повреждённых файлах. Отдельно — реальное восстановление из резервной копии в изолированном окружении с измерением RPO/RTO, проверкой целостности и прав.

## 8. Онлайн, конкуренция и аварии

Проверить 2/5/20 одновременных редакторов, одновременный ввод в одном абзаце, параллельное перемещение/удаление блока, изменение одной ячейки, восстановление старой версии и изменение прав в активной сессии. Ввести сбои: отключение сети, высокий RTT, потери пакетов, переключение Wi-Fi/LTE, закрытие вкладки, обновление страницы, перезапуск сервера, истечение сессии, повторная доставка событий, смена ведущего узла. После синхронизации не допускаются незаметная потеря или дублирование подтверждённых изменений. Для несливаемых операций показывать разрешение конфликта и сохранять обе версии до выбора. Состояния «локально», «сохраняется», «сохранено», «ошибка» должны соответствовать действительности.

## 9. Качество UX, скорость и визуальные регрессии

Для критичных пользовательских сценариев провести прямое сравнение с Notion на одинаковых устройствах и задачах: создать страницу, вложить страницу, оформить текст, перенести блок, изменить таблицу, увеличить изображение, поделиться, найти документ, восстановить версию. Измерять время выполнения, число действий, ошибки пользователей и субъективную ясность; устранить обоснованные отставания. Зафиксировать SLO как проектные целевые значения с последующей калибровкой: локальный отклик типовых действий p95 ≤100 мс; появление контекстной панели p95 ≤150 мс; открытие уже загруженной страницы p95 ≤500 мс; стабильная анимация на целевых устройствах преимущественно 60 fps; синхронизация между клиентами p95 ≤1 с при нормальной сети. Эти числа не считаются доказанными до измерений. Тестировать 320/375/768/1024/1440/1920 px, zoom 100/125/150/200%, светлую/темную тему если реализована, Safari/Chrome/Firefox/Edge, iOS/Android, длинные строки, переполнение, всплывающие меню у границ и большие деревья.

## 10. Надёжность, безопасность, эксплуатация

Тестировать роли и наследование прав, личные/гостевые/временные доступы, отзыв во время открытой сессии, вложения, поиск и экспорт под ACL; не допускать обходов через прямой URL/API. Провести нагрузочное, длительное (soak), стрессовое, регрессионное, доступностное и отказоустойчивое тестирование; проверить наблюдаемость, метрики, алерты, журналы без секретов, миграции схемы, откат релиза, процедуры поддержки и инструкции восстановления. Выполнить тестирование на тестовом окружении, максимально соответствующем production, затем контролируемую пилотную эксплуатацию с реальными сотрудниками.

## 11. Доказательства и релизный шлюз

Каждый сценарий имеет статус PASS/FAIL/BLOCKED/NOT APPLICABLE с обоснованием, ссылку на запись запуска и версию сборки. Обязательны CI автотесты, end-to-end браузерные тесты, visual regression скриншоты, ручной UX-аудит, мобильные жесты на реальных устройствах и повторная регрессия после каждого исправления. Перед релизом: 100% инвентаризированных пользовательских действий покрыты проверками; 100% критичных и высокорисковых сценариев пройдены; 0 открытых blocker/critical дефектов; 0 известных сценариев потери подтверждённых данных, обхода ACL и необратимого повреждения архива; остальные дефекты документированы и не ухудшают эксплуатацию. Сдать отчёт о покрытии, протоколы восстановления, измерения производительности, реестр решений, руководство администратора и операционные runbooks. Если критерии не достигнуты — релиз запрещён; цикл исправление → повторный тест продолжается до соответствия.

## 12. Риск-ориентированная матрица комбинаций

Нельзя ограничиваться одиночными тестами. Для каждой функции провести pairwise-комбинации по осям: роль/доступ × устройство/ввод × тип контента × сеть × параллельность × история × размер данных. Для критичных путей — сценарии из 3–7 последовательных действий и хаотические property-based/fuzz тесты. Отдельно фиксировать инварианты: данные не исчезают; порядок и иерархия корректны; права не расширяются без подтверждения; экспорт-импорт сохраняет поддерживаемую семантику; все изменения имеют достоверное состояние сохранения; интерфейс не имеет пересечений и некликабельных целей.


# Дополнение v2.7 — пространства, UX и защита данных

## v2.7. Пространства как основной контур прав

Базовое правило: права задаются на уровне пространства и групп подразделений. Статьи и вложенные страницы наследуют права по умолчанию. Индивидуальные исключения допускаются только осознанно, с явной маркировкой и объяснением эффективных прав.

## Модель пространств

Личное (закрыто по умолчанию); общекорпоративное (все сотрудники); подразделение (группа сотрудников и руководителей); закрытое (участники по приглашению); гостевой проект (минимально необходимый доступ). Режимы видимости пространства: открытое, закрытое с видимым названием, приватное и невидимое посторонним. Администратор может определить шаблон пространства и права по умолчанию.

## Повседневный сценарий сотрудника

Создать статью кнопкой + у раздела, без отдельного выбора прав. Статья наследует родителя, появляется в дереве, фокус сразу в названии; автосохранение и черновик включены. Создание дочерней статьи, перенос drag-and-drop, копирование и публикация требуют минимального числа действий. Исключения доступа не показывать до запроса пользователя.

## Повседневный сценарий администратора

Завести сотрудника, назначить подразделение/группу и роль, автоматически предоставить доступ к соответствующим пространствам. Перевод между отделами пересчитывает эффективные права с предпросмотром. Временные приглашения, гости, приостановка, отзыв активных сессий и массовое управление группами. Экран «Почему пользователь видит этот документ?» раскрывает цепочку наследования и исключений. Журнал изменений прав с возможностью аудита.

## Безопасность наследования и перемещений

Нельзя незаметно расширять аудиторию переносом страницы между пространствами. Перед расширением видимости показать конкретное изменение и запросить подтверждение. Не допускать доступа через вложения, поиск, миниатюры, API, экспорт, историю версий и кэш после отзыва прав. Проверять разрешения на сервере; по умолчанию запрет при неоднозначности. Приватные материалы не включать в общие индексы и уведомления.

## Надёжность данных и восстановление

Сохранять подтверждённые операции в устойчивом журнале, выполнять идемпотентную синхронизацию и контролировать версии/конфликты. Локальная очередь при офлайне, явный статус «сохранено/синхронизируется/требуется внимание». История операций, версии, корзина и восстановление отдельного блока/страницы/дерева с сохранением последующих ревизий. Регулярно проверять резервные копии реальным восстановлением, контрольными суммами и сравнением импорт-экспорт-импорт.

## UX: предугадывать намерения, не мешать

Контекстные действия появляются только когда нужны; в навигации стрелка раскрывает, название открывает, + создаёт дочернюю страницу. Умные значения по умолчанию, последняя используемая позиция, быстрый поиск, клавиатурные действия, отмена и понятная обратная связь. Никаких обязательных диалогов для типовых операций. Предупреждения только при необратимом действии или риске изменения видимости.

## Сквозная приёмка v2.7

Проверить: новый сотрудник видит нужные пространства; перевод между отделами; создание 100 дочерних страниц без ручной настройки ACL; приглашение гостя на один раздел; отзыв доступа при открытой странице; скрытое пространство отсутствует в поиске/уведомлениях; перенос приватной страницы в общую с предупреждением; одновременный перенос и правка; сбой сети и перезапуск сервера во время редактирования; восстановление удалённого дерева; импорт/экспорт с вложениями, ACL и ссылками; сравнение с Notion на одинаковых ежедневных задачах. Для каждого сценария фиксировать время, количество кликов, ошибки, отсутствие потери данных и визуальные дефекты. Релиз запрещён при непроверенном критичном сценарии или риске утраты данных.
